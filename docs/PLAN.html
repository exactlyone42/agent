SQLite 適不適合

建議單機 CLI／Tauri 用 SQLite 保存任務；同機一個任務擁有者控制執行。知識索引仍用本機 PostgreSQL／pgvector，資料庫不共用任務真相。SQLite 的優點是免架伺服器、交易完整、可隨程式交付；不是因為資料小才用，也不代表它能替我們執行或停止工作。

別人的做法：Codex 的 state 模組使用 SQLite，本輪讀到實際連線設定及狀態、佇列等資料庫路徑；其 rollout 資料與 SQLite 並存，不能說全部執行都只靠 SQLite。Codex 原始碼。LangGraph 把流程快照與跨任務記憶分開；官方把 SQLite 列為本機開發保存方式，PostgresSaver 用於持久服務，不能把 SQLite 套件存在說成大型服務推薦。LangGraph 保存設計

動作 SQLite 保存什麼 執行核心必須做什麼
執行 領取者、嘗試次數、工具意圖、回執、驗證結果 短交易搶任務；模型與工具執行時不持有資料庫交易
授權 誰批准哪個工具、參數摘要、範圍、有效期限與使用狀態 執行前再次核對；參數或範圍改變就重新判斷，不能沿用籠統批准
取消 先存取消請求，之後存已停止或結果未明 禁止新工具、停止子程序並核對；遠端操作可能已生效，不能假稱回滾
接續 已完成步驟、未完成意圖與外部操作識別 先核對舊執行者已停止；未知副作用查外部回執，不能直接再做一次

本案採單一任務資料庫、WAL（讓讀取與寫入較少互相阻塞）與短交易；同時仍只有一個寫入交易。重要授權及執行意圖以 FULL 同步設定驗收，鎖等待與重試有上限；資料庫只放本機磁碟，不放 NFS 或同步雲端資料夾。備份用 SQLite 備份介面，不只複製仍在寫入的主檔。官方適用範圍、WAL 限制

取消與領取必須在同一資料庫條件更新，避免取消後又派發。接續使用執行世代識別，舊執行者的回報不可覆蓋新狀態；這個識別本身不能阻止外部工具繼續寫，仍須實際停止舊程序。無法確認停止時維持「結果未明」，禁止重啟有副作用步驟。資料庫交易無法和任意外部 API 形成一次性交易；優先使用工具支援的冪等識別（重送也不重複執行），否則查證或人工處理。

補充取消契約：領用一次性授權與寫入工具「準備執行」意圖，必須在同一短寫入交易檢查任務世代及取消狀態；意圖不等於工具已啟動。單一執行者將派發與取消處理串行化，啟動後另存回執，崩潰空窗標為結果未明。每條寫入連線設定 FULL 與有限鎖等待。工作區用作業系統鎖確保唯一寫入者；執行者以程序身分、心跳與所屬程序群組追查，心跳超時不等於已死亡。確認可控程序樹已停止、待派工作已撤銷，才回報本機取消完成；10 秒觀察只是額外故障測試，不能代替終止證據。遠端工具另查狀態，無法確認就不宣稱已停止。

採 Codex 時優先沿用它的執行與保存介面；平台只保存平台授權、任務映射與獨立驗收，不複製另一份核心執行進度。所有工具入口必須受平台政策約束，不能攔住的核心不能通過 P01。採 Rig 時則由平台保存主流程。P01 同題驗證這個邊界，禁止兩套迴圈同時控制任務。Computer Use 也走同一意圖與回執契約，帶觀察序號、時間及視窗身分；P07 再依實測增加欄位，不預造未使用的資料表。

授權真相保存在任務 SQLite；文件有效版本與來源權限資料在知識庫，查詢由核心先驗範圍，再由知識服務核對來源；送模型前再次驗授權世代及來源版本，不聲稱跨兩庫交易。Memory 的同意、候選與有效內容映射採 SQLite 初版提案，內容可指向受限產物；詳見 agent-method.md 的修訂契約，仍待 P06 驗收。資料庫不可用或權限狀態無法核對時拒絕提供片段。

P01／P04 要測兩程序搶同任務、授權與取消競爭、工具前後崩潰、磁碟滿、鎖超時、資料升級及備份恢復；先不宣稱效能或可靠接續已通過。若未來跨機 worker 要共享任務，或量測顯示寫入等待破壞互動目標，再採伺服器任務庫；不讓遠端程序直接開 SQLite 檔。
