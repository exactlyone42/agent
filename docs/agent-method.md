# 整個 Agent 如何工作：方法、證據與驗收

研究日期：2026-10-26。這份文件是全案運作契約與研究決策，不是實作完成報告。主計畫保留 CLI → ADE／IDE 的交付方向；知識細節見 [knowledge-plan.md](knowledge-plan.md)。本文件補足先前只研究局部能力的缺口；產品與發布範圍以唯一 [主計畫](../PLAN.md) 為準；本文件只定義執行契約，發現衝突須同步修正，不能另立主計畫。

## 先定方向，不把功能名稱當成答案

採一個可替換的執行核心（Harness），把模型決策、工具執行、任務紀錄及獨立驗收分開。第一版單一 Agent；明確步驟用程式，未知步驟才讓模型選下一個動作。模型不能直接批准自己、改完成條件、忽略取消或把自評存成成功。Gateway 只供模型 API，不接管本機授權。

證據分三種：**規範／官方實作**說明介面與現有做法；**論文實驗**只支持特定資料、模型與任務的結果；**本案決策**須以實際試接驗收。以下「常見工程做法」指能在官方產品或框架找到，不代表已量測市場占有率；「研究支持」不代表全領域保證有效。不以預印本自稱同行審查通過。

## 執行中連續輸入（待實作）

同一任務的補充、修正與提問先保存原文，依接收順序編號；介面顯示已接收、等待處理及已套用，不把收到當成已執行。每則訊息有客戶端識別碼，重送不重複處理；保存失敗要明確回報，不可假裝已收。不同任務各自獨立；同一工作區仍遵守單一寫入者。

執行核心在模型回覆結束、工具回執已記錄等安全邊界，依序處理已收到的訊息；連續訊息可一起交給模型理解，但不得丟失原文、改變順序或將推測當成使用者指示。新輸入不自動取消正在執行的工具；下一個有副作用的動作派發前必須先處理已接收的訊息並重新核對任務版本與授權。對話摘要須保留原目標、有效限制、未處理訊息及證據索引，需要時讀回原文。

使用者明確要求停止時，取消優先，不等一般訊息排隊：立即停止派發新動作，依取消契約處理正在執行的工具，並區分已停止與結果未明。補充或修正預設保留原任務，只有明確要求放棄或替換才改變目標；衝突且無法判定時先停止受影響動作並詢問。修正產生新任務版本，舊計畫與不再適用的授權失效；已發生的副作用保留紀錄，不因改指令而視為撤銷。

避免無限積壓：限制每則大小及每任務待處理數量，超限明確拒絕並保留已接收內容；實際上限與介面延遲須在 P04 實測後定案。模型只整理和建議，程式保存順序、執行狀態及核權；無證據的推測不得升格為事實，完成仍須獨立驗證。此策略尚未實作或驗收。

## 審查後補齊：最小欄位與執行規格

以下是待實作的 schema 規格，不是已存在的資料表。識別用字串 UUID，時間用 UTC，金額用固定精度；所有紀錄帶 schema_version。程序只接受已知版本與列舉值，未知欄位依協定版本規則拒絕或明確忽略，不靠模型猜。

| 紀錄         | 最小欄位                                                                                                                 | 唯一寫入責任                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------- |
| TaskSpec     | task_id、spec_revision、original_request_ref、workspace_id、goal、criteria[]、policy_revision、budget、state、generation | 平台核心；模型只能提出候選，使用者修正產生新版                       |
| Criterion    | criterion_id、type（file/api/gui/semantic）、expected_ref、verifier_id、required、reviewer_role                          | 固定任務模板或使用者原需求決定，獨立驗收者鎖定；執行模型無權自行降低 |
| ToolIntent   | call_id、task_id、step_id、generation、tool_version、args_ref、args_hash、approval_id、idempotency_key、status           | 核心派發端；意圖與授權領用同一交易                                   |
| Approval     | approval_id、principal、scope、tool_version、args_hash、policy_revision、expires_at、uses_remaining、revoked_at          | 授權服務；使用者已授權範圍可由政策判定，不由模型批准                 |
| Receipt      | call_id、attempt_id、status、external_ref、artifact_refs、started_at、finished_at、error_code                            | 工具執行端提交，核心驗來源及世代後保存；模型文字不當回執             |
| Event        | event_id、task_id、seq、generation、type、payload_ref、created_at                                                        | 核心追加；task_id＋seq 唯一，重播不派工具                            |
| Evidence     | criterion_id、verifier_version、artifact_hashes、observed_state、verdict、checked_at                                     | 獨立驗證器；產物與規則改變就失效                                     |
| Memory       | memory_id、principal、workspace_scope、content_ref、source_refs、consent_id、status、valid_from、expires_at、revision    | 記憶服務，模型僅送 candidate；有效性與同意由程式／人工核定           |
| SourceAccess | source_id、principal、scope、policy_revision、source_version、status、checked_at                                         | 知識服務保存主機可讀檢查結果；不是自行授權。來源取回時重驗           |

任務規格與 Evidence 保存於平台 SQLite；大內容放使用者專屬的受限檔案。Memory 初版的候選、有效內容與來源映射也用平台 SQLite（有界內容或檔案引用），先按使用者／工作區／期限篩選再查內容；沒有需要時不增加向量記憶系統。與知識庫來源連動用來源版本及撤回事件，讀取端再次查有效性，不能聲稱跨庫交易。這是對此前 P06 保存位置未定的明確修訂。

記憶不接受工具回應裡的「請永遠記住」作同意。使用者明示偏好可依其範圍保存；AI 摘要與失敗經驗先為候選，附可讀回證據。撤回後立即停止注入模型，衍生快取同步失效；實際刪除及備份保存期按使用者授權處理，不擅刪資料。

### 合法狀態與完成條件

| 目前狀態                     | 可前往                                                                 | 必要條件                                             |
| ---------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------- |
| queued                       | running、cancel_requested                                              | 核心取得工作區鎖與執行世代；取消優先核對             |
| running                      | waiting_approval、verifying、failed、cancel_requested、outcome_unknown | 真實事件觸發；不得因模型文字直接成功                 |
| waiting_approval             | running、failed、cancel_requested                                      | 批准有效且對應當前規格；拒絕不轉為批准               |
| verifying                    | succeeded、running、needs_review、failed、cancel_requested             | 全部必要條件通過才成功；修正尚有預算才回 running     |
| cancel_requested             | cancelled、outcome_unknown                                             | 可控程序確實停止且外部結果已核對，否則結果未明       |
| outcome_unknown              | verifying、cancelled、failed                                           | 查得真實回執後由恢復協調者決定；禁止直接重新派副作用 |
| needs_review                 | verifying、cancel_requested                                            | 等待具名驗收者或補足可執行判準，不再自動修正         |
| succeeded、failed、cancelled | 不直接重開                                                             | 接續建立新 run／generation，先核對舊程序與已生效動作 |

開放式研究、設計與寫作仍有可檢查項目（必答問題、來源、產物、格式）；語意正確及是否滿足目的由獨立人工規準驗收。沒有足夠判準時可交候選產物，但狀態是 needs_review，不冒稱 succeeded。AI 評審僅提供建議，不能修改 criteria；人類驗收也留版本與理由。

### 模型與 CLI 協定

本輪唯讀核對 Gateway 的 `src/routes.rs:34–39`，確實登記 `/v1/chat/completions`、`/v1/responses`、`/v1/messages`；路由存在不證明目前每個模型或 Codex 都相容。P01 的能力表必含 wire_protocol、model_id、streaming、tool_schema、parallel_calls、image_input、context_limit、cancellation、usage_reporting。每個值帶實測版本，未知即不啟用該能力。Codex 路線先測 Responses 端到端，Rig 路線依已選 provider 的原生協定；未通過不做不明轉譯補丁。

串流只在工具參數完整且驗 schema 後執行；call_id 對應回覆，不從文字猜工具名。串流中斷與重連可重播事件但不得再次領用授權。必過條件是所有工具含內建 Shell 均可限制、最後派發可核對授權／取消、外部可停止執行、結果可獨立讀回；任一不過即淘汰核心候選。

CLI 契約保留 run/resume/status/doctor，補 cancel、approve/deny、events。非互動批准必帶 approval_id 與預期 spec_revision；輸入走 stdin 或受限檔，不在命令列帶秘密。事件用逐行 JSON，欄位沿用 Event；stdout 只放結構化結果，診斷放 stderr。events 接 after_seq，桌面透過隨應用啟停子程序使用同協定；schema 不相容拒絕，不解析終端文字。斷線後先 status／補事件，不能把重新連線當 resume。未知命令及無效狀態不得觸發工具。

### 隔離與平台的具體選擇

Windows／macOS／Linux 均須滿足同一隔離契約，Linux x64 試接選 **bubblewrap 隔離一次性 Shell**：唯讀基本 runtime、明列工作區可寫、獨立暫存、預設無網路，不掛 SSH agent 或完整主機 HOME；[官方](https://github.com/containers/bubblewrap)明確指出隔離強度取決於呼叫參數，不是裝了就安全。缺 user namespace 或必要限制時拒絕敏感工具，不靜默退回裸 Shell。模型網路由核心走 Gateway，Shell 需要網路則另走已批准能力。

常駐解析／索引仍在容器；優先試非 root 執行與明確 UID 映射，來源唯讀掛載，parser 無網路，資料庫只供內部服務。[Docker rootless](https://docs.docker.com/engine/security/rootless/)有主機先決條件，安裝器檢查，不自動調整使用者系統服務。主機 GUI 只由使用者啟動的前景 CLI／桌面子程序呼叫既有驅動，不把主機桌面 socket 全開給背景容器；Linux 隔離試接先用 X11；Windows／macOS 原生桌面與 Linux 受支援會話須各自完成 P07，均不得降為後續選項。

憑證採 OS keyring 優先，無可用 keyring 時才用使用者專屬 0600 設定檔；啟動不得寫入一般日誌或傳給 Shell／parser，平台能力 probe 必含秘密 canary。這些均為選型提案，未在此輪安裝或驗證。

P05a 最小試接可用合成工作區資料，但產品仍是授權全機漸進發現；不得把測試起點縮減成最終需求。依序測單範圍、跨範圍不同權限、整機大量清單，再驗常駐更新。2 CPU／4 GiB 先約束基準解析與索引，不保證 OCR／大型語言模型能同時運行；無法容納就排程延後或重新選型，不放寬限制冒充合格。

### 樣本與判定補充

30 題×5 次只作 P01/P02 比較篩選，不是產品發布認證。固定種子／版本並列每題五次結果；按任務家族做成對重抽樣區間，避免把同題五次當完全獨立的 150 題。安全案例以是否出現未授權副作用判定，任何一次即拒收該版本，但零次不表示真實風險為零。成效選型需目標指標改善且成本不超標，區間重疊或分組退步就標示證據不足。發布前擴充到全部宣告任務類型、真 Client 與原全套驗收，不用這 30 題代替。

### 複審後明確化的三個邊界

**Codex 事件保存**：平台 Event 是顯示、政策及驗收用的事件投影，不是 Codex 執行狀態的第二個寫入者。增加 origin、source_session_id、source_event_id 或 source_offset；以來源識別去重，來源進度與投影同一 SQLite 交易提交。Codex 核心事件透過其支援的介面同步，平台不得直接改寫其執行狀態；平台取消／批准是命令請求，收到核心回執才形成對應事實。若固定版本無可靠事件識別或恢復途徑，就以 P01 同題驗證是否能安全重建；不能做到即淘汰。Rig 路線則平台本身是執行事件的來源。Event 表中的「核心追加」應按此區分來源與投影寫入者。

**記憶升格**：使用者明示要保存的偏好，在原訊息可定位、scope 明確、有效同意存在且無互斥新版時，由程式轉有效；不需要模型再猜同意。從任務學到的經驗必須附獨立驗證成功的 Evidence，且其適用條件可表達成明確範圍；無法由規則核對的經驗須具名人工確認，否則留 candidate。來源撤回、驗證版本變更或新偏好衝突時先失效；AI 生成的摘要不能只靠自己提供引用就升格。

**來源權限映射**：source_id 與內容雜湊分開；每個 source_id 保存授權根目錄、主機使用者 UID/GID、相對路徑與檔案識別、政策世代及有效來源版本。容器用該使用者的明確映射，只掛授權根目錄；不得以容器 root 的可讀性當主機權限。身份／ACL 無法可靠映射的來源標為不支援，不能全允許。內容去重可共享計算，但每次引用必經來源各自授權；跨來源摘要須同時有權讀全部依據。SourceAccess 是可撤銷的核對結果，不是新的授權來源；檢索、補讀與送模型前都核對當前政策，原文以同身分實際開啟並檢查版本。測兩個根目錄同內容不同權限、撤銷群組存取、符號連結換目標與檢查後檔案替換；任何狀態未知都拒絕片段外送。這些為試接契約，未宣稱消除了所有競爭空窗。

## 工具、授權與隔離：真正阻擋動作的位置

[S5 MCP tools 規範 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)定義工具與 schema，不自動替應用程式提供權限隔離。內建工具、MCP、Shell、瀏覽器及 Computer Use 必須共用授權決策；把 MCP 設成安全不代表 Shell 就不能繞過。

授權紀錄綁使用者／任務、工具版本、正規化後參數摘要、路徑或服務範圍、期限及可使用次數。已有持續授權照用，不能每一步都再問；超出範圍才請使用者決定。LLM 只提出請求，程式在最後派發點核對。寫檔時核對實際開啟的目標，不能只比字串路徑；Shell 的任意子程序與網路權限要由實際隔離環境限制，不只靠命令黑名單。

工具回應是資料，不可冒充上層指示；外部內容同樣不可授權外送、寫檔或安裝。設定來源允許清單、只讀掛載、輸出上限、程序及網路限制，憑證由工具端取得，模型不接觸原始秘密。已批准不代表對該工具所有未來參數永久放行。

## 上下文、記憶與知識：三種不同的保存

- **任務進度**：確定性的動作、授權與回執，不能只靠模型摘要恢復。
- **短期上下文**：目前模型看見的目標、最近觀察、必要原文與事件摘要；可壓縮，但原始證據在受限產物保存，普通日誌不含全文。
- **長期記憶**：經同意保存的使用者偏好與已驗經驗，附來源、時間、範圍及撤回方式。不是自動把所有聊天當成永久事實。

## 三塊 RAG 放在整個 Agent 的哪裡

向量化 RAG 提供證據搜尋；Agentic RAG 是同一 Harness 裡的主動查證任務；知識庫保存版本化來源、可核對知識與解答。不是三個自行批准／循環的 Agent。詳細格式、全機漸進建庫、語意切片與虛擬問題見 [knowledge-plan.md](knowledge-plan.md)。

本案初始搜尋基準：結構切片、原文向量、關鍵字搜尋、去重與原文引用。優先比較重新排序與補回上下文；再分別加語意切片、問題多向量、背景說明與多問法。E5 候選依其正規化規格使用內積；cosine、內積、L2 的選擇依模型，不能與 HNSW／IVFFlat 近似索引混為一談。索引加速要對照相同權限條件下的精確搜尋，測近似找回率、更新積壓與熱門篩選後回傳不足。

## 資料保存、重試、取消與恢復

SQLite 保存平台任務／授權／事件；知識內容與向量留 PostgreSQL；大型附件與受限回執留檔案，記路徑與雜湊。採 Codex 時核心進度以其介面為準，SQLite 只存平台映射與政策。任務、授權及事件需一起提交的資料放同一資料庫短交易；跨資料庫不能宣稱原子完成。

[S11 LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)區分快照與跨任務記憶；[checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers)說明保存機制。這支持保存與恢復的分層，不證明外部副作用恰好執行一次。採 SQLite 的 WAL、FULL 同步、備份及限制見 [S12 官方](https://sqlite.org/wal.html)。

2026-10-27 實作前補查：SQLite 官方記錄多連線同時寫入／收整日誌可能觸發 WAL-reset 資料損壞，3.51.3 起已修正，另有指定舊版修補。新實作固定使用至少 3.51.3 的已修補版本，啟動及驗收讀回實際 SQLite 版本，不只看 Rust 套件版本；WAL 僅用本機檔案系統，不把網路磁碟當成支援部署。來源：[官方缺陷與修補說明](https://www.sqlite.org/wal.html#the_wal_reset_bug)。Rust 候選採 rusqlite 的明確交易介面，失敗預設回滾；尚未加入依賴或通過持久任務驗收。

狀態契約：queued、running、waiting_approval、cancel_requested、cancelled、verifying、needs_review、succeeded、failed、outcome_unknown。只有獨立驗證通過才能進 succeeded；取消請求不等於 cancelled；結果未明不可盲重送。排程器先檢查已有任務與執行者，不能因心跳逾時就同時派第二份。

有副作用工具先在短交易保存意圖與領用授權，之後派發並保存回執。資料庫寫入與作業系統啟動間仍有空窗，必須由單一執行者序列化派發／取消，重啟核對程序身分與外部回執。每次嘗試有獨立識別及世代；舊世代回報不可覆寫新世代，但世代欄位本身阻止不了外部寫入。

取消先停止派發，再停止本機可控程序樹，最後查證；遠端服務已開始的行為未必可撤回。無法確認時保留 outcome_unknown。補償動作不是回滾，若會刪除或產生新副作用，仍須相應授權。10 秒沒有寫入僅是案例觀察，不能當取消保證。

模型請求與工具請求分開重試：429 尊重 Retry-After；超時、串流中斷先查現況，沒有回執不等於沒執行。只讀請求可有界重試；具副作用請求必須有冪等識別或查證途徑。模型切換只發生在清楚的步驟邊界，不重送已派工具；保留版本變更事件，禁止用另一模型掩蓋待查證狀態。

## 電腦操作與使用者介面

優先穩定 API／檔案工具；必須操作畫面時採既有驅動，沿用 observe/action/verify/cancel 契約。驅動是否支援Windows／macOS／Linux 各自的顯示環境、無障礙樹、截圖及輸入，須逐項試接；候選名稱不代表已支援。每個操作綁當次觀察與視窗；焦點或縮放改變先重新觀察。鎖屏、休眠與使用者搶回輸入時停止派發並記狀態。

CLI 先支援任務、授權、取消、接續及結果；ADE 共用同一資料與事件。介面重連依事件序號補讀，重送批准帶識別避免二次領用。關窗前景任務依產品契約停止或交接容器 worker，不默默變常駐。IDE 與修改 Orca 仍是後續取捨，六家產品比較留在主計畫，不能從競品有桌面推導我們必須重造編輯器。

## 安裝、觀測、升級與效能也是方法的一部分

原生 CLI 不依賴 RAG 服務才能啟動；完整知識版在本機容器提供依賴。安裝器先檢查平台、容器、磁碟、來源範圍、模型大小與授權，缺項明示，不默默花錢或上傳。鎖定可執行檔版本、依賴 lockfile、容器 digest、模型 revision 及授權；升級須驗 schema 遷移、備份還原及不相容拒絕。下載校驗與簽章信任來源分開，不能只看同站 SHA 就稱供應鏈安全。

每任務記 task/run/step/tool call 識別、時間、狀態、重試、模型用量與驗收位置；普通日誌不記秘密與完整資料。原始證據放受限產物，有保存與撤回規則；錯誤不能吞。保存範圍也納入磁碟預算，達限暫停新工作，不自動刪使用者資料。常駐程序遵守容器及 loopback 限制；單次 CLI 子程序不冒稱常駐服務。
