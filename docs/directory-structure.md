# 目錄結構與檔案歸屬

這份是 repo 目錄的唯一正式地圖。新增檔案前先查這裡，找得到歸屬就直接放；找不到再看文末的核准規則。`cargo xtask gate` 的第一步會用 Git 追蹤的檔案比對本表，違反就失敗。

## 頂層

| 項目            | 放什麼                                                                                                                                          | 不可放                  |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| `crates/`       | 所有 Rust 套件，一個子資料夾一個 crate                                                                                                          | 散檔、非 crate 的資料夾 |
| `docs/`         | 繁中白話文件與圖形成品（PDF）；一模組一份                                                                                                       | 程式、產生的暫存檔      |
| `loops/`        | 全案 LOOP 與各票據、檢查點                                                                                                                      | 第二份 LOOP、說明文件   |
| `scripts/`      | 開發維運用的小工具與政策設定                                                                                                                    | 產品邏輯                |
| `.repo-policy/` | 共用 Git 政策與 hooks 安裝                                                                                                                      | 專案程式                |
| `.cargo/`       | cargo 別名與變異測試設定                                                                                                                        | 其他設定                |
| 根目錄檔案      | `README.md`、`PLAN.md`、`HANDOFF.md`、`DEVELOPMENT.md`、`AGENTS.md`，`.gitignore`、`.prettierignore`，以及 Cargo、npm、toolchain 的設定與鎖定檔 | 實作檔、筆記、暫存檔    |

## crates 內部

每個 crate 只放三樣：`Cargo.toml`、`src/`、`tests/`。需要 `build.rs`、`examples/`、`benches/` 這類新項目，屬於結構變更，要先核准。

| crate       | 責任                                                           | 不可含               |
| ----------- | -------------------------------------------------------------- | -------------------- |
| `harness`   | 自寫的 agent 迴圈與事件契約                                    | 特定模型或服務的接線 |
| `http`      | 模型呼叫共用的 HTTP 連線與逾時，格式由各接線提供               | 特定服務的請求格式   |
| `openai`    | 對 OpenAI 相容 Gateway 的接線                                  | 批准、任務庫         |
| `anthropic` | 對 Anthropic 訊息格式的接線                                    | 批准、任務庫         |
| `approval`  | 敏感工具的批准閘門                                             | 模型呼叫             |
| `agent`     | 任務、任務庫、輸入檢查、驗證結果，以及把批准閘門接到任務的程式 | 命令列解析           |
| `cli`       | 命令列入口與輸出                                               | 核心邏輯             |
| `xtask`     | 快檢與完整檢查                                                 | 產品功能             |

## 檔案與命名

- 獨立函數一檔一個；型別連同它的方法同檔（見 AGENTS.md）。
- 不建 `misc`、`common`、`helper(s)`、`util(s)`、`shared`、`temp`、`tmp` 目錄，任何層級都不行（檔名可以含這些字，資料夾名不行）。需要共用時，先找真正擁有該職責的 crate。
- 測試放各 crate 的 `tests/`；測試輔助放 `tests/support/`。

## 結構變更的核准

| 動作                                                    | 誰決定                    |
| ------------------------------------------------------- | ------------------------- |
| 在既有 crate 的 `src/` 或 `tests/` 內新增檔案或子資料夾 | AI 自行決定，要有明確職責 |
| 新增 crate、頂層項目、crate 內新項目，或調整上表        | 先取得使用者同意          |
| 大量搬移、刪除或合併既有模組                            | 先取得使用者同意          |

核准後，同一個提交要一起改這份文件與 `crates/xtask/src/structure_violations.rs` 的登記表，兩邊不一致就是錯。

## 完成前自查

- 新增的檔案與資料夾是否都在上表有歸屬。
- 是否已有同職責的檔案或 crate，被重複建立。
- `git status` 與 `git diff --stat` 有沒有意外產生的檔案。
