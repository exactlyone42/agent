# 工具完成後遇到資料庫忙碌

結果保存只對 SQLITE_BUSY 有界重試；不重送工具或模型。重試窗口為兩秒，每次資料庫等待最多 500 毫秒，間隔 200 毫秒，因此最後一次等待可能超過兩秒窗口。其餘錯誤立即停止，取消也會結束重試。

依據 [SQLite 交易說明](https://www.sqlite.org/lang_transaction.html)：BEGIN IMMEDIATE 遇其他寫入者會回 BUSY，COMMIT 因 BUSY 失敗時交易仍有效。本機 rusqlite 0.41.0 的 transaction.rs 已讀回：交易預設離開時回滾，成功 commit 才結束。因此重試範圍限於資料庫交易；不把其他 I/O 錯誤當成可盲重送。

實際 CLI 故障注入在成果檔同步前用管線通知測試端，測試端取得資料庫寫鎖才放行工具，以確定鎖發生於結果保存，而非批准之前。三個新案例通過：鎖住 0.9 秒後恢復成功；持續鎖住時五秒內退出而非無限等待；等待中取消保留成果且記錄結果未確認。批准使用次數均為零，沒有重新取得批准；成功案例僅一次工具請求及一次最終模型回覆。

執行：`python3 scripts/test_cli.py CliContract.test_manual_approval_controls_real_tool_execution`，退出 0，9.360 秒。測試包含既有批准、拒絕、版本錯誤、過期、派送失敗、結果保存失敗及取消案例。

故障注入依賴 Linux；Windows、macOS 實機尚未驗證。持續鎖住也會阻擋最終收尾，因此可能保留最後紀錄狀態，不能據此宣稱執行程序仍存活；恢復功能仍待實作。未部署，企業發布門檻未完成。
