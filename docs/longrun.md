# 長任務如何接手

本PLAN是執行清單，單一任務紀錄仍沿用 `/home/cash/.cache/agent-platform-decisions/loops/agent-platform-decisions.loop.md`；不得為同一全案開第二份LOOP、重複排程或平行分支。開發目錄為 `/home/cash/work_space/private/agent-platform`，原Gateway研究工作區與證據保留。

## 第一次實作的入口

1. 讀PLAN、現況與原LOOP最近checkpoint；確認Git分支、未提交內容、Orca終端與執行者。看到其他執行者正在寫入時不搶工作區；先做唯讀研究。
2. 選第一個前置條件全過的PENDING步驟。現在從P01開始；只能在真正驗收後記DONE，不能因為寫了規範或空crate就跳到P02。
3. 實作近期一小段、跑能推翻它的正反測試、讀回結果，再決定下一段。一輪至少交付一個可驗切片或新的阻塞證據，不能每五分鐘重報同樣狀態。
4. 狀態變動才用 `bash ~/tools/cash-rule-checkpoint` 記錄，禁止手改checkpoints.jsonl；記目標、實際證據、未證明事項與唯一下一步。

## 五分鐘續跑

原排程名稱 `agent-platform-decisions`，ID `ad8983b6-1875-4762-8031-1a12b989a6aa`。先查是否已停用、是否仍有執行者，不自動建立第二個。此輪是交付可執行PLAN，沒有宣稱已啟動產品背景開發；接續實作時沿用既有五分鐘要求與宿主排程，具體啟用狀態必須讀回。

每輪輸入固定為原始目標、最新使用者決策、PLAN、最近checkpoint與證據位置。排程只觸發檢查，不另起重疊工作。執行者用repo級獨占鎖加run ID/心跳；逾時先查程序與最後副作用，不因鎖過期就直接再執行。背景產品worker在容器，開發CLI可互動執行。

每輪上限先設一個驗收切片；等待編譯用既有程序的等待介面，不能重開編譯。連續兩輪無新證據就換方法；記錄已試方法與退出碼。單一模組受阻時繼續不相依項目，不能再次只擴做取消問題。

## 停止與恢復

只有整體驗收完成、缺必要人類決定/授權，或直接證據顯示已無可推進工作才停止。停止時停用原排程並讀回enabled=false，附停止原因、已做/未做、阻擋命令與最小下一步。阻塞不等於產品完成，不能把P01–P10改DONE。

不得增加花費、正式部署、刪除使用者資料或授權。必要付費模型或實機缺口先做免費/離線替代與獨立工作；最後仍必要才具體列缺口，不把研究問題丟回使用者。

中斷後先核對Git、事件、容器與產物，不盲重送可能有副作用的命令。沿用相同run的證據；新嘗試另立run ID，保留失敗結果。合成fixture可依既定清理範圍重建，使用者原始資料不得重寫。
