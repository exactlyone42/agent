# 變異測試：不需測試的改動與平台缺口

變異測試會故意改壞程式一小處，看測試能不能發現。有些改法不會改變任何行為，測試本來就不可能發現，叫「等價改動」。排除清單放在 `.cargo/mutants.toml`，每一項都要在這裡說明原因；新增排除必須先證明真的等價。

## 既有排除項目

| 位置                                    | 為什麼改了也沒差                                                                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| input.rs 第 52 行 `\|` 改 `^`           | 兩個旗標的位元不重疊，合併與互斥結果相同                                                                                            |
| result.rs 第 72 行 `+` 改 `*`           | 讀取上限 `FILE_LIMIT + 1` 變成 `FILE_LIMIT`；開檔時已先擋掉超過上限的檔案，只有檔案在檢查後又變大才會走到，測試無法穩定製造這個瞬間 |
| store.rs 第 146 行                      | 比的是 SQLite 版本下限；本機版本遠高於下限，換比較符號結果不變，需換另一版 SQLite 才能分辨                                          |
| store.rs 第 150、158 行 `\|` 改 `^`     | 旗標原本就沒有該位元，`^` 與 `\|` 相同；`&` 的改法已由符號連結測試抓到                                                              |
| store.rs 第 176 行 `<` 改 `<=`          | 版本已是最新時多跑一次升級交易，內容與結果相同                                                                                      |
| store.rs 第 190 行                      | 剛設定完的檢查，設定成功後不可能不符                                                                                                |
| approvals.rs 第 78 行（參數總長度上限） | 超過上限與否，後面的工具參數檢查都回同一個錯誤，外部看不出差別；乘號改法由逸出字元測試抓到                                          |

這些沿用的例外含版本及競爭情境的測試缺口，不能當作所有情境都等價的證明。

## 不跑變異的入口

`crates/xtask/src/task.rs` 的 `Task::run` 與 `Task::all` 只負責啟動整套檢查，測它們等於在測試裡再跑一次完整檢查；它們的內容由 `check_all` 與 `run_steps` 的測試涵蓋，所以這兩個函式的整體替換不進變異清單（寫在 `crates/xtask/src/plan.rs`）。

## 平台缺口：只在 Windows 編譯的程式

input.rs 第 42、82、90、103 行屬於 Windows 專用程式，Linux 不會編譯，所以變異永遠「沒被抓」。`crates/xtask/src/check_all.rs` 在非 Windows 平台排除這幾行；依 2026-10-31 決定，Windows、macOS 只做相容設計、不做實機驗證，這些行永遠不會被變異測試驗收，維持排除。`identity_guard` 與 `file_identity` 現有測試只在 Windows 執行，所以本 repo 不宣稱 Windows 已支援。`single_link.rs` 第 11 行（非 Unix 版本，固定回傳「只有一個連結」）同樣只在 Windows 編譯，同樣排除；Windows 上還沒有測試能分辨硬連結，此缺口只記錄、不補實機測試；若日後要支援 Windows，須先重開實機驗證決定。
