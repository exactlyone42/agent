# 變異測試：不需測試的改動與平台缺口

變異測試會故意改壞程式一小處，看測試能不能發現。有些改法不會改變任何行為，測試本來就不可能發現，叫「等價改動」。排除清單放在 `.cargo/mutants.toml`，每一項都要在這裡說明原因；新增排除必須先證明真的等價。

## 已排除的等價改動（Linux 實測確認過其他漏抓都已補測試）

| 位置                                     | 為什麼改了也沒差                                                                           |
| ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| input.rs 第 40 行 `\|` 改 `^`            | 兩個旗標的位元不重疊，合併與互斥結果相同                                                   |
| store.rs 第 84 行                        | 比的是 SQLite 版本下限；本機版本遠高於下限，換比較符號結果不變，需換另一版 SQLite 才能分辨 |
| store.rs 第 88、96 行 `\|` 改 `^`        | 旗標原本就沒有該位元，`^` 與 `\|` 相同；`&` 的改法已由符號連結測試抓到                     |
| store.rs 第 114 行 `<` 改 `<=`           | 版本已是最新時多跑一次升級交易，內容與結果相同                                             |
| store.rs 第 135 行                       | 交易內的二次檢查，外層已先擋過；只有兩個程序同時改資料庫才會走到                           |
| store.rs 第 160 行                       | 剛設定完的檢查，設定成功後不可能不符                                                       |
| approvals.rs 第 132 行（參數總長度上限） | 超過上限與否，後面的工具參數檢查都回同一個錯誤，外部看不出差別                             |
| approval.rs 第 146 行                    | 比較的是剛好等於期限的瞬間，時間無法精準重現                                               |

## 平台缺口：只在 Windows 編譯的程式

input.rs 第 30、61、69、82 行屬於 Windows 專用程式，Linux 不會編譯，所以變異永遠「沒被抓」。`scripts/check_all.py` 在非 Windows 平台排除這幾行；Windows 實機必須不排除並跑完（`identity_guard` 與 `file_identity` 現有測試只在 Windows 執行）。Windows 實機結果出來前，這塊不能宣稱已驗收。
