## 原始回覆

**結論：可有條件進入 P01 試接**（Codex／Rig 比較＋SQLite 壓測）。整機 RAG、GUI、電腦操作現在不可試接。我沒開任何來源連結，所以各來源是否支持主張，我都沒查證。

1. **完成條件沒人負責。** 任務規格由 AI 整理，卻要求獨立驗證器判成功。開放式任務（寫報告、研究）沒有驗證器，也沒有「無法驗證」這個終態。請補：完成條件誰定、驗證器分幾類、無法驗證時算什麼。
2. **核心未定，卻有兩套進度來源。** 選 Codex 時進度歸它，取消、恢復、授權攔截可能不在平台手上。P01 要先訂必過門檻：能攔截全部工具、能在派發點注入授權、能由外部取消，不過就淘汰。
3. **隔離只有原則，沒有機制。** 沒選 Shell 沙箱（bwrap、Landlock 或容器）、網路控制、憑證存放處。「常駐只在容器」也與要操作主機檔案或桌面的 worker 位置衝突，沒解決。
4. **沒有具體契約。** 任務、事件、授權、回執沒有欄位定義，也沒有合法狀態轉移表、寫入者，更沒有 CLI 指令面與事件協定。P01 前至少交一份 schema。
5. **模型協定空白。** 「能力契約」沒定義。Gateway 提供哪種協定、串流與工具呼叫是否相容 Codex，都沒寫。
6. **記憶無契約。** 存哪、怎麼取回、如何防止不可信內容被寫進記憶，都沒寫。
7. **RAG 範圍過大。** Docling、LlamaIndex、PostgreSQL、容器、E5 疊四層，再加全機權限映射，卻沒有權限資料表設計。2 CPU／4 GiB 能否跑 OCR 沒有依據。P05a 請先縮到工作區。knowledge-plan 抬頭寫「已審查修訂」，內文卻說新章節未審，狀態自相矛盾。
8. **驗收與介面未決。** 30 題×5 次樣本小，沒有判定規則或信賴區間。CLI 與 Tauri 桌面的關係、Linux 顯示環境（X11 或 Wayland）也未決。

**來源與保證：** 方法文件大多已標明「論文結果不外推」，我沒看到明顯把論文當保證的偷換。但「常見工程做法」的說法沒有證據。
