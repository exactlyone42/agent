**審查結論：不可放行。** 只讀了你貼的文字，沒有用工具，也沒有測過產品。

1. **【阻擋】企業門檻沒有落到工作步驟。** 身分與政策、稽核、簽章、軟體材料清單、備份還原、容量這幾項，在 P01–P10 和 delivery-steps 的 12 步裡都沒有負責步驟。身分權限雖寫「P01 定案」，但 P01 的驗收只看選核心。修正：加一張「門檻項目→負責步驟→驗收→具名責任人」對照表，缺列者不得標正式。

2. **【阻擋】發布範圍互相矛盾。** 一處說 CLI 通過自己範圍即可單獨正式交付，另一處說任何正式發布都要過全門檻，其中包含桌面。修正：定義 R1（CLI＋核心＋知識）和 R2（加桌面）兩個發布範圍，各附能力矩陣。

3. **【阻擋】RAG 驗收不能執行。** R01 只寫「開發前固定門檻」，沒有 Recall@10、nDCG@10、延遲或容量的數字。R01–R15 沒對應到 P05a、P05b、P03b。P05a 還寫「最小流程」，與非 MVP 的要求衝突。R15 要所有方法都比對，沒有收斂條件。修正：先寫入各項數值門檻和負責步驟，再開工；R15 設實驗預算和停止條件。

4. **【阻擋】安裝仍不清楚。**

   - 簽章是門檻，卻寫「簽章費用另議」，P03a 又只交 SHA-256。
   - Docling 和 LlamaIndex 是 Python，要明說放在容器內，並確認授權可離線再散布。
   - 修正：定出唯一支援的容器環境和安裝者，簽章改成 R1 必備。
