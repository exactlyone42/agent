## agent-method.md
# 整個 Agent 如何工作：方法、證據與驗收

研究日期：2026-10-26。這份文件是全案運作契約與研究決策，不是實作完成報告。主計畫保留 CLI → ADE／IDE 的交付方向；知識細節見 [knowledge-plan.md](knowledge-plan.md)。本文件補足先前只研究局部能力的缺口；衝突時以本文件明列的修訂為準，原安全與品質門檻不降低。

## 先定方向，不把功能名稱當成答案

採一個可替換的執行核心（Harness），把模型決策、工具執行、任務紀錄及獨立驗收分開。第一版單一 Agent；明確步驟用程式，未知步驟才讓模型選下一個動作。模型不能直接批准自己、改完成條件、忽略取消或把自評存成成功。Gateway 只供模型 API，不接管本機授權。

證據分三種：**規範／官方實作**說明介面與現有做法；**論文實驗**只支持特定資料、模型與任務的結果；**本案決策**須以實際試接驗收。以下「常見工程做法」指能在官方產品或框架找到，不代表已量測市場占有率；「研究支持」不代表全領域保證有效。不以預印本自稱同行審查通過。

## 一次任務的完整交付契約

| 環節 | 交給 AI | 交給程式與現成組件 | 必須留下的交付物／驗收 |
| --- | --- | --- | --- |
| 接收任務 | 把自然語言整理成目標、未知資訊、建議步驟 | 保存原指令、任務 ID、工作區、權限、預算、完成條件與版本 | 任務規格；缺必要資訊才詢問。測歧義、多目標、取消與使用者中途修正；新修正使舊計畫及不適用授權失效 |
| 選模型與核心 | 可提供任務分類建議，不決定外送權限 | 按能力契約選 Gateway 模型；沿用 Codex／Rig 比較，不另造主迴圈 | 固定模型、核心、工具 schema 版本；測結構化工具、串流、不支援能力及斷線；不能默默改模型後沿用舊結果 |
| 組裝上下文 | 可摘要歷史，提議需要補讀的資料 | 保留目標、限制、授權、待辦與證據索引；按需載入原文，限制輸入大小 | 摘要不是原始真相；測壓縮前後限制、取消及未完成步驟是否保留，不能只驗字數縮小 |
| 規劃與執行 | 提出下一步、工具參數與可檢查的預期結果；看到實際回應再調整 | 狀態轉移、步數／時間／費用限制、重複動作偵測 | 計畫版本、動作與觀察紀錄，不要求保存隱藏思考全文；測無進展迴圈、工具失敗及預算耗盡 |
| 查資料 | 選搜尋問法、拆子問題、核對證據缺口 | 三塊 RAG、來源讀取權限、版本與快取；沿用 Docling／LlamaIndex 候選 | 原文位置、版本、查證時間；測無答案、矛盾、舊資料、虛擬問題誤導與跨檔依據 |
| 呼叫工具 | 提議工具及結構化參數 | 型別／schema 驗證、授權核對、隔離執行、超時、輸出大小限制；MCP 用現成 rmcp 候選 | 固定 call ID、參數摘要、執行意圖、回執；測未知工具、錯型別、重複回覆、惡意工具文字與串流半截參數 |
| 寫檔／外部動作 | 產生修改候選，不自行發布 | 檢查差異、原檔版本、路徑與能力範圍；原子替換適用檔案，外部服務依其冪等契約 | 修改前後雜湊／差異與外部回執；測原檔被別人修改、符號連結換目標、逾時但外部已成功 |
| 電腦操作 | 根據最新觀察辨識目標與動作 | 既有驅動，檢查視窗、觀察序號、縮放、焦點及權限；每次動作後重取狀態 | 動作回執＋實際畫面／檔案結果；測彈窗、焦點切換、過期截圖、座標縮放及取消。先在隔離桌面，不能直接全機代操 |
| 取消與接續 | 可解釋已做／未做，不能決定是否忽略取消 | 停止新派發、終止可控程序樹、核對外部狀態、鎖定單一執行者並保存進度 | 已停止、失敗或結果未明的證據；測每個有副作用步驟前後崩潰及等待批准時重啟 |
| 驗證與修正 | 根據失敗證據提議修正，必要時輔助語意審查 | 獨立驗證器讀回檔案、DB、UI 或外部狀態；限定修正次數 | 每項完成條件的證據；故意輸入偽成功文字、假回執、只完成部分要求，驗證必須不過 |
| 記憶與知識發布 | 提出可重用經驗、摘要與答案候選 | 使用者同意、來源與版本、有效期限、衝突與撤回；無證據者不升格成事實 | 記憶候選與同意紀錄；測跨工作區洩漏、使用者更正、忘記與舊偏好失效 |
| 對使用者交付 | 用白話解釋成果與限制 | 從實際驗收組裝狀態，不採模型自稱完成 | 可開啟產物、逐項結果、未完成原因、使用版本；CLI 與桌面讀同一事件，重連不再執行工具 |

## 執行核心與計畫策略的取捨

**基準採單 Agent＋有界工具迴圈**。固定格式轉換、檔案發現、權限、重試排程與驗收全部由程式控制；多步研究與未知環境操作交給模型決定下一步。一次規劃整個長任務可能因環境變更失準，所以保存小步計畫與明確完成條件，觀察後再修正。

[S1 ReAct](https://arxiv.org/html/2210.03629v3)在 HotpotQA、FEVER、ALFWorld、WebShop 評估推理與動作交錯。原 Table 1 中 ReAct 在 HotpotQA 的 EM 為 27.4，Standard 為 28.7，CoT-SC 為 33.4；因此不能說加入 ReAct 就全面變好。本案借用「觀察後再動作」，不把論文提示模板硬套所有現代工具模型。

[S2 τ-bench](https://arxiv.org/html/2406.12045v1)在零售與航空的政策／API 任務，以最終資料庫狀態驗收。其方法比較顯示原生 function calling 在所測模型優於文字格式工具，另加 think 工具未提升。故本案優先原生工具呼叫與 schema，不用自然語言文字解析當執行協定；實際可用仍由 P01 同題測試決定。

[S3 Anthropic 2024 工程經驗](https://www.anthropic.com/research/building-effective-agents)區分固定流程與模型自主選動作；其頁面已提醒工具生態變更。本輪另讀 [2026 Managed Agents](https://www.anthropic.com/research/managed-agents)：分開 session、harness、sandbox。本案借介面邊界，不導入其雲端服務，不宣稱這是對本機 Rust 的效能實驗。

| 候選 | 決策 | 為什麼／何時改變 |
| --- | --- | --- |
| Codex app-server 與 Rig | 保留原 P01 同題比較；先不宣告勝者 | 看實際授權、取消、恢復與工具攔截能力；Codex 自有紀錄不再複製成第二套真相 |
| 先固定完整計畫再跑 | 只適用步驟已知任務 | 長任務用短步計畫並根據觀察修訂；失敗不能悄悄改完成條件 |
| Reflexion 式反思 | 有外部失敗證據才試，最多 2 次修正為初始比較設定 | [S4](https://arxiv.org/html/2303.11366v4)在 ALFWorld、HotpotQA 及程式題有提升，但有局部最優與測試不完備限制；不是讓 AI 反覆自評就變正確 |
| 多 Agent | 初版不作預設；只讀、可獨立子題先試 | 任務包含輸入範圍、權限、期限、交付與驗證；子代理不能提升父權限，同一工作區仍單寫入者。必須在相同總模型預算下勝過單 Agent，不能用更多花費冒充方法有效 |
| 複雜樹狀搜尋／自我辯論 | 暫不作通用基礎 | 可驗證候選的規劃題再試；目前無本案證據支持全任務收益，成本與驗證器弱點會放大 |

## 工具、授權與隔離：真正阻擋動作的位置

[S5 MCP tools 規範 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)定義工具與 schema，不自動替應用程式提供權限隔離。內建工具、MCP、Shell、瀏覽器及 Computer Use 必須共用授權決策；把 MCP 設成安全不代表 Shell 就不能繞過。

授權紀錄綁使用者／任務、工具版本、正規化後參數摘要、路徑或服務範圍、期限及可使用次數。已有持續授權照用，不能每一步都再問；超出範圍才請使用者決定。LLM 只提出請求，程式在最後派發點核對。寫檔時核對實際開啟的目標，不能只比字串路徑；Shell 的任意子程序與網路權限要由實際隔離環境限制，不只靠命令黑名單。

工具回應是資料，不可冒充上層指示；外部內容同樣不可授權外送、寫檔或安裝。設定來源允許清單、只讀掛載、輸出上限、程序及網路限制，憑證由工具端取得，模型不接觸原始秘密。已批准不代表對該工具所有未來參數永久放行。

[S6 AgentDojo](https://arxiv.org/html/2406.13352v3)以 97 任務與 629 攻擊案例測工具回應注入。工具隔離在部分案例有效，但同一工具既能完成正事又能做壞事時仍失效。故防線不能只有提示文字或偵測模型；同時報正常任務成功與受攻擊後的成功，避免靠全部拒絕得到假安全。

## 上下文、記憶與知識：三種不同的保存

- **任務進度**：確定性的動作、授權與回執，不能只靠模型摘要恢復。
- **短期上下文**：目前模型看見的目標、最近觀察、必要原文與事件摘要；可壓縮，但原始證據在受限產物保存，普通日誌不含全文。
- **長期記憶**：經同意保存的使用者偏好與已驗經驗，附來源、時間、範圍及撤回方式。不是自動把所有聊天當成永久事實。

[S7 Lost in the Middle](https://arxiv.org/abs/2307.03172)在多文件 QA 與鍵值搜尋發現位置影響，不能直接外推所有新模型；[S8 Anthropic context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)提供按需讀取與壓縮的工程做法。採任務必要資訊優先，而不是塞滿上下文。壓縮後重跑限制保留、證據可讀回與工具未完成案例；摘要失真則回原始事件重建。

[S9 LoCoMo](https://arxiv.org/abs/2402.17753)包含多輪長期對話、時序及問答，顯示長上下文／RAG 仍有缺口。本案借測試類型，加入「偏好被更正」「只對某工作區有效」「使用者要求忘記」；不拿聊天記憶分數證明任務恢復安全。原 LangChain／LangGraph／LangSmith／Rig／Swiftide 比較仍有效，沒有官方 Rust 等價證據的套件仍標社群候選。

## 三塊 RAG 放在整個 Agent 的哪裡

向量化 RAG 提供證據搜尋；Agentic RAG 是同一 Harness 裡的主動查證任務；知識庫保存版本化來源、可核對知識與解答。不是三個自行批准／循環的 Agent。研究方法與結果限制另見 [RAG 論文比較](retrieval-evidence.md)。詳細格式、全機漸進建庫、語意切片與虛擬問題見 [knowledge-plan.md](knowledge-plan.md)。

本案初始搜尋基準：結構切片、原文向量、關鍵字搜尋、去重與原文引用。優先比較重新排序與補回上下文；再分別加語意切片、問題多向量、背景說明與多問法。E5 候選依其正規化規格使用內積；cosine、內積、L2 的選擇依模型，不能與 HNSW／IVFFlat 近似索引混為一談。索引加速要對照相同權限條件下的精確搜尋，測近似找回率、更新積壓與熱門篩選後回傳不足。

[S10 CRAG](https://arxiv.org/html/2406.04744v2)區分即時、快變、慢變及固定事實；標準答案綁查詢時間。本案因此對問題分類設定查證時間，而非宣稱五分鐘更新就永遠最新。失聯時標示狀態，不把舊答案發布成最新；外送片段與公開來源查詢均受原權限控制。

## 資料保存、重試、取消與恢復

SQLite 保存平台任務／授權／事件；知識內容與向量留 PostgreSQL；大型附件與受限回執留檔案，記路徑與雜湊。採 Codex 時核心進度以其介面為準，SQLite 只存平台映射與政策。任務、授權及事件需一起提交的資料放同一資料庫短交易；跨資料庫不能宣稱原子完成。

[S11 LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)區分快照與跨任務記憶；[checkpointers](https://docs.langchain.com/oss/python/langgraph/checkpointers)說明保存機制。這支持保存與恢復的分層，不證明外部副作用恰好執行一次。採 SQLite 的 WAL、FULL 同步、備份及限制見 [S12 官方](https://sqlite.org/wal.html)。

狀態契約：queued、running、waiting_approval、cancel_requested、cancelled、verifying、succeeded、failed、outcome_unknown。只有獨立驗證通過才能進 succeeded；取消請求不等於 cancelled；結果未明不可盲重送。排程器先檢查已有任務與執行者，不能因心跳逾時就同時派第二份。

有副作用工具先在短交易保存意圖與領用授權，之後派發並保存回執。資料庫寫入與作業系統啟動間仍有空窗，必須由單一執行者序列化派發／取消，重啟核對程序身分與外部回執。每次嘗試有獨立識別及世代；舊世代回報不可覆寫新世代，但世代欄位本身阻止不了外部寫入。

取消先停止派發，再停止本機可控程序樹，最後查證；遠端服務已開始的行為未必可撤回。無法確認時保留 outcome_unknown。補償動作不是回滾，若會刪除或產生新副作用，仍須相應授權。10 秒沒有寫入僅是案例觀察，不能當取消保證。

模型請求與工具請求分開重試：429 尊重 Retry-After；超時、串流中斷先查現況，沒有回執不等於沒執行。只讀請求可有界重試；具副作用請求必須有冪等識別或查證途徑。模型切換只發生在清楚的步驟邊界，不重送已派工具；保留版本變更事件，禁止用另一模型掩蓋待查證狀態。

## 電腦操作與使用者介面

優先穩定 API／檔案工具；必須操作畫面時採既有驅動，沿用 observe/action/verify/cancel 契約。驅動是否支援目前 Linux 顯示環境、無障礙樹、截圖及輸入，須逐項試接；候選名稱不代表已支援。每個操作綁當次觀察與視窗；焦點或縮放改變先重新觀察。鎖屏、休眠與使用者搶回輸入時停止派發並記狀態。

[S13 OSWorld](https://arxiv.org/html/2404.07972v2)採真實應用環境與獨立狀態／檔案驗證；早期模型分數不拿來描述今天模型。本案學其驗收方法：點擊成功不等於任務成功，最後要讀回存檔、設定或應用結果。視覺模型可幫忙檢查，但不能自己當唯一裁判。

CLI 先支援任務、授權、取消、接續及結果；ADE 共用同一資料與事件。介面重連依事件序號補讀，重送批准帶識別避免二次領用。關窗前景任務依產品契約停止或交接容器 worker，不默默變常駐。IDE 與修改 Orca 仍是後續取捨，六家產品比較留在主計畫，不能從競品有桌面推導我們必須重造編輯器。

## 安裝、觀測、升級與效能也是方法的一部分

原生 CLI 不依賴 RAG 服務才能啟動；完整知識版在本機容器提供依賴。安裝器先檢查平台、容器、磁碟、來源範圍、模型大小與授權，缺項明示，不默默花錢或上傳。鎖定可執行檔版本、依賴 lockfile、容器 digest、模型 revision 及授權；升級須驗 schema 遷移、備份還原及不相容拒絕。下載校驗與簽章信任來源分開，不能只看同站 SHA 就稱供應鏈安全。

每任務記 task/run/step/tool call 識別、時間、狀態、重試、模型用量與驗收位置；普通日誌不記秘密與完整資料。原始證據放受限產物，有保存與撤回規則；錯誤不能吞。保存範圍也納入磁碟預算，達限暫停新工作，不自動刪使用者資料。常駐程序遵守容器及 loopback 限制；單次 CLI 子程序不冒稱常駐服務。

## 問題多向量的具體比較契約

每片原文保存版本與權限；AI 可產生最多 3 個不同且能被原文回答的問題作初始試驗設定。每題保存支持位置，模型生成欄位與原文分開。方案 A 只索引原文，B 將原文與問題串接，C 每題獨立向量並映射回原文；三組用同一回答模型、相同候選原文數及上下文預算。

C 命中後先按原文識別去重，再用使用者問題與原文重新排序；不能以命中問句數相加，讓生成較多問題的文件不公平占滿結果。各路分數未校準前用排名融合，不直接相加 cosine 與全文分數。不同表示的 E5 前綴須明定為檢索 query/passage 或對稱問題匹配並分組驗證，不混用未標示設定。

向量模型 revision、tokenizer、pooling、正規化與維度一起固定；不同模型的向量不可混比，即使維度相同。模型升級建新版本索引，驗收後切換；來源更新或撤權，所有衍生問題與摘要先失效。全文、向量、快取及回答都不能繞過權限與有效版本檢查。

## 必須報出的效果與代價

品質：Recall@10、nDCG@10、答案正確與引用支持、拒答、跨文／中文／數字／否定／時效分組。成本：首次與增量建庫、索引容量、模型用量、p95/p99 查詢、峰值記憶體。HNSW 的近似找回率另對照完整搜尋；數學距離等價不保證不同近似索引回同一候選。

先單項消融（只加一種方法），再測組合；以文件家族與時間隔離開發與最終題庫。合成問題可用於開發，不得把索引中的問句或近似問句作獨立驗收。固定重複次數，報波動與分項退步；沒有改善就移除，不把所有方法疊上當成熟方案。

### 知識與解答如何保存

每筆知識與可重用解答至少保存：適用問題與範圍、內容、來源識別及版本、支持段落、來源發布／修改時間、最後成功查證時間、下次檢查時間、有效期限、讀取權限、生成模型／提示版本，以及有效、待查證、衝突、撤回狀態。查證時間與來源修改時間分開，不能用重新生成時間冒充來源更新。

解答要記錄依賴哪些來源版本；來源更新、刪除、權限撤銷時，所有依賴解答、摘要、模擬問題與快取都先失效，再安排核對或重算。跨來源答案採來源權限交集，不因整理成摘要就擴大可見範圍。跨步驟的失效通知須可持久保存、重送及去重；當通知尚未處理，讀取端仍核對來源版本，不能依賴通知絕不遺失。

經人工整理、具名負責者確認、或可由明確規則與原始數據核對的內容，可按各自發布規則成為有效知識；僅由 AI 生成的內容標為候選。通過哪些核對必須可讀回，不把所有內容都標成相同程度的可信。

### 高頻維護，不等於高頻重算全庫

下面是本案初始排程提案，不是實測承諾，也不代表可以無限制呼叫外部來源：

- 本機資料：異動事件即時排入更新，合併短時間連續儲存；沿用已監看小檔在無排隊時 60 秒內更新的待驗目標。熱門範圍每 5 分鐘核對缺漏，其他目錄以有界批次輪替，初始目標 24 小時內覆蓋一輪；資料量超過能力時明列落後時間。
- 外部資料：只對已配置且獲准來源維護。優先使用來源提供的變更通知或條件式請求；快速變動來源先以 5–15 分鐘、穩定來源以每日檢查作候選，遵守限流與成本設定。對價格、即時狀態等問題，在回答前查即時來源，不以定時快照保證最新。
- 已保存解答：來源事件觸發失效，熱門或快到期解答優先核對。低頻解答可在下次使用時重驗；過期或有衝突時先標示待查證，不能為維持可用而冒充最新。
- 維護失敗：保留重試位置、有限次數與退避間隔，顯示最後成功查證時間及原因。來源不可用、權限不足與確定刪除分開，不以失聯推論已刪除。
- 不變的資料不重新解析或向量化；模型生成只用在真正變更或需要改善的項目。維護工作與前景查詢共用既有資源預算，超量就顯示積壓與暫停狀態，不默默耗滿電腦。

「總是最新」作為產品目標，落地契約是：回答帶最後查證時間及適用範圍；使用前核對有效性；無法確認最新就明說並轉入查證。外部來源本身延遲、漏事件或不可用時，不能承諾世界發生變化的同一瞬間就已更新。

### 維護與 Agentic RAG 的專項測試

建立帶可控制時鐘的本機檔案與假外部來源：發布新版、回傳未變更、限流、斷線、撤權、刪除、同名不同內容、兩來源矛盾、事件重送／遺失，以及失效後發布前崩潰。確認相關答案立即轉成待查證，未受影響答案保留；過期資料不能被快取或模擬問題繞過檢查。

Agentic RAG 用有標準證據的多步問題驗收：查不到時是否改問法、是否補齊跨文件條件、遇衝突是否如實呈現、是否在預算內停止。模型輸出與真實工具紀錄分開核對；故意提供錯誤引用與偽造完成文字，驗證它們不能直接發布知識。

監控分別顯示來源查證落後時間、更新佇列最久等待、待查證／衝突答案數、失效傳播耗時、漏更新與錯誤引用數，以及維護資源用量。前述品質增強候選繼續保留；本次三塊分工與維護條款尚未經 Claude Code 再審，未實作或實測。

## 採用的方案

安裝後即可交代任務，索引在背景執行；不等待掃完整顆硬碟。先發現檔案位置、大小與格式，再按用途解析內容、依結構切片、建立向量。正在工作的資料先做，大型手冊與報告另有處理名額；其他資料持續補齊，更新只處理有變動的文件及片段。

推薦組合是 **Rust 入口與工作控制＋Docling 解析／切片＋LlamaIndex 處理管線＋本機 PostgreSQL／pgvector**。Rust 用現成 walkdir 與 notify 做檔案發現和異動通知。這是待試接的組合，不是已互通的產品；不重寫解析器、向量引擎、OCR 或第二套 Agent 迴圈。

| 責任                     | 復用什麼                               | 本案只補什麼                                                     |
| ------------------------ | -------------------------------------- | ---------------------------------------------------------------- |
| 列出檔案與異動通知       | Rust walkdir、notify                   | 範圍政策、工作順序、缺漏核對、重啟續跑                           |
| 文件解析與結構切片       | Docling；按需要選其本機 OCR            | 隔離呼叫、版本及頁碼／表格／附件位置映射                         |
| 程式結構                 | Tree-sitter 的 Rust 介面與對應語法套件 | 將函式／型別及行號交給切片階段，不自寫 TS／Rust 語法分析         |
| 批次處理、快取、文件識別 | LlamaIndex IngestionPipeline           | 穩定識別、版本發布與範圍契約；禁用自動掃全庫刪除策略             |
| 全文與向量查詢           | PostgreSQL＋pgvector                   | 僅查目前有效版本及有權限來源；中文檢索另驗                       |
| 本機向量模型             | multilingual-e5-small 作首個測試候選   | 固定模型版本、批次大小與查詢／文件前綴；若品質不過再比較替代模型 |

LlamaIndex 內建文件雜湊判定和處理快取，但不保證我們的解析器參數、權限與多表更新自然一致，必須補同版測試。[處理管線](https://developers.llamaindex.ai/python/framework/module_guides/loading/ingestion_pipeline/)

### 為什麼沒有直接裝所有研究過的工具

- **Recoll** 適合現成全文搜尋與電子郵件；它的「只即時監看部分目錄，其餘定期核對」值得採用。但同時加入它與另一套知識資料庫，會增加兩套索引、解析與失效同步。本案先用它作檔案搜尋品質對照。[官方監看說明](https://www.recoll.org/usermanual/webhelp/docs/RCL.INDEXING.MONITOR.html)
- **sist2** 有檔名快速掃描、內容限制與增量掃描，適合作效能對照；不是把完整文件結構交給 RAG 的現成保證。其內容截取上限不能冒充全文件已讀。[官方用法](https://github.com/sist2app/sist2/blob/master/docs/USAGE.md)
- **Khoj** 有同步與片段雜湊復用，可參考處理方法，但不另啟完整聊天／Agent 平台。[原始碼](https://github.com/khoj-ai/khoj/blob/master/src/khoj/processor/content/text_to_entries.py)
- **Swiftide／langchain-rust** 保留比較資格；此次優先 Docling 與 LlamaIndex 是為了復用文件結構與既有處理管線，不為了全 Rust 再造 Python 已有能力。若同題試接證明 Rust 組合更簡單且品質不退，再修訂選型，不能同時養兩套。

## 安裝與部署

首個驗收平台為 Linux x64。CLI 是原生程式；長駐的索引服務、Python 解析與 PostgreSQL 都在本機容器，埠只綁 127.0.0.1。解析器不連網、不執行文件巨集、不取得模型供應商憑證。來源讀取按主機使用者身分檢查，容器不得靠 root 身分繞過主機權限；已允許的來源以唯讀掛載供索引服務讀取，輸出與資料庫使用獨立資料目錄。

完整產品安裝包含容器環境檢查、已核准的本機模型與服務啟動；不要求使用者手工建資料表。若容器或模型缺少，基本 CLI 仍可工作，畫面明列「知識庫尚未就緒」，不能宣稱整機功能已裝好。尚未取得的模型與套件大小、授權、版本在試接前核對，不偷偷下載或用付費 API 補上。

CLI 關閉不關閉已啟用的索引服務；提供暫停、繼續、查看進度與停用。索引服務與任務工具的取消分開：停止一次 Agent 任務不等於清除知識庫；暫停建庫要停止後續內容處理並保存位置。

macOS／Windows 之後另驗本機事件與容器掛載；不能把 Linux 的監看能力直接推論到 Docker Desktop。notify 官方列有網路磁碟、容器與監看數量限制，偵測失效時改分區定期核對，而非假稱即時。[notify](https://docs.rs/notify/latest/notify/)

## 全機發現與有順序的處理

「全機」指目前使用者獲准可讀的本機磁碟與資料來源，並非只看當前 repo。安裝時展示範圍與排除規則；預設納入文件、下載、桌面、專案與其他可讀資料目錄，背景逐個補齊其他目錄。額外磁碟逐個列明；雲端未下載項目、加密容器、其他使用者資料及應用程式線上帳號各自標示邊界。

快速發現只讀目錄與檔案資訊，不先讀每個大檔做全文雜湊，也不保證列完整機瞬間完成。以小批目錄保存位置；當前工作區與明確點名檔案可先處理，不等全機發現結束。檔名副檔名先篩選，再以檔頭辨認實際格式；不能只靠副檔名斷言支援。

候選優先序：使用者正在問的檔案、當前工作區、文件／下載／郵件資料、大型知識文件、其餘資料。大型檔案依格式與用途進獨立佇列，不把大於某大小當作無價值而永久跳過；大型影片、備份與編譯產物也不因體積大而擋住手冊。前景查詢與大檔解析分開排程，但仍共用總資源上限；以前景保留資源與背景最久等待時間驗收，不用檔案數比率冒充公平。長時間未處理者提高優先度；不能中途接續的大檔只在足夠空閒時安排，避免反覆中止後重做。

暫存、快取、套件目錄、編譯輸出與我們自己的索引目錄預設不做內容索引；敏感憑證資料不向量化，預設排除 .ssh、.gnupg、.env 及其變體、瀏覽器設定檔、密碼庫與 .git 物件歷史；這些規則不是能找出所有秘密的保證。安裝時以整體範圍清單取得一次同意，之後自動進行，不要求每個檔案逐一批准。隱藏目錄不是一律排除，仍按類型判定。排除範圍可見，不能把排除計入完成。符號連結不跨出已授權範圍、不循環追蹤；重複檔可共用內容計算，但各路徑與讀取權限分開保存。

## 解析、切片、向量化

| 類型與例子                                   | 解析及切片方式                                             | 初版目標與邊界                                                                                          |
| -------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| PDF、DOCX、PPTX、MD、HTML                    | Docling 保留章節、頁碼、表格；依結構切片                   | 先支援文字文件；掃描 PDF 走本機 OCR，慢工作另排，不阻塞其他文件                                         |
| XLSX、CSV、ODS                               | 保留工作表、欄名、資料列與範圍；表頭隨片段保留             | 不把整本表格壓成摘要；公式與顯示值分開，不執行巨集，不宣稱能重算 Excel                                  |
| EML、MSG、郵件附件                           | 先抽主旨、寄件人、時間、內文及郵件關聯；附件作子文件       | Docling 的附件名稱不是附件內容解析，須把附件交給對應解析器；PST／OST／MBOX 為另行試接項目，不冒充已支援 |
| TS、TSX、RS 等原始碼                         | Tree-sitter 按函式／型別切片，保留路徑、行號與必要上層名稱 | 不執行原始碼；結構切片不等於完整跨檔呼叫分析                                                            |
| LaTeX、JATS XML 等專業文件                   | 使用文件解析器支援的結構；公式、表格及引用位置保留         | 每種格式獨立驗收；不能把任意 XML 視為同一規格                                                           |
| SVG、PNG、JPG 與設計預覽                     | 提取文字／本機 OCR、保留來源與圖面位置                     | 視覺內容尚未理解者明列；OCR 不等於理解設計語意                                                          |
| DXF、DWG、PSD、AI、FIG、STEP、IFC 等設計原檔 | 先登記格式及可用預覽；專用工具逐種評估                     | 不宣稱通用解析器能讀懂。DXF 可試 ezdxf；DWG 及其他原檔的結構、圖層、尺寸與元件須獨立驗證                |

以上是要交付的支援矩陣，不是本輪已跑過的格式。Docling 官方列格式及必要額外依賴，舊 DOC／XLS 等轉換可能需 LibreOffice。[格式清單](https://docling-project.github.io/docling/usage/supported_formats/)、[Tree-sitter](https://tree-sitter.github.io/tree-sitter/)、[ezdxf 邊界](https://ezdxf.readthedocs.io/en/stable/introduction.html)

流程先產生可重用的結構化解析結果，再切片，最後向量化。每片保留文件版本、來源位置、解析器與切片設定；章節名稱、表頭可補到片段，但不可覆寫原文。Docling HybridChunker 可按結構與模型長度分割／合併並重複表頭，直接復用，不自行按固定字數粗切。[切片文件](https://docling-project.github.io/docling/concepts/chunking/)

模型先試本機 multilingual-e5-small，按模型要求區分 query／passage 前綴，切片長度與 tokenizer 對齊；不把模型宣告的多語能力當中文、程式碼、表格檢索已合格。未通過固定題庫就改候選，不能改題目遷就模型。[模型來源](https://huggingface.co/intfloat/multilingual-e5-small)

大檔先登記、提取可取得的目錄與頁面資訊，再以解析器確實支援的頁段／工作表單位處理；不假設每種檔案都能串流或任意切開。不能分段的格式在隔離程序內整檔解析，超過時間／記憶體上限就標示延後或失敗，保留原因與下次策略，不永久無聲跳過，也不無限重跑。

## 異動、刪除與接續

原生事件只用來加速，並非完整真相。先啟動監看並緩衝事件，再列出範圍，核對掃描期間異動；事件合併後批次處理。常用目錄即時監看，其餘輪流核對檔案資訊；重啟或事件溢出時重查受影響目錄。移除磁碟、權限不足與確認刪除分開，不因磁碟沒掛載就清除全庫。

單文件流程為：發現版本 → 解析 → 切片 → 向量就緒 → 發布。解析前後核對來源是否改變；變了就不發布混合版本。新一版未完成前，舊版標示過期且預設不回答；新版驗證完整後才切換有效版本。每個工作有固定識別與單一執行者，崩潰後查已完成階段再續跑。

LlamaIndex 文件識別、處理快取與資料庫的有效版本是不同責任：快取鍵必須包含片段實際內容、解析／切片設定、模型與向量維度；不能因路徑相同就重用。LlamaIndex 的快取可能受批次與 metadata 影響，必須實測片段重排與來源版本變更；若不能穩定復用，先以其公開介面接固定的逐片快取鍵，不直接宣稱內建已做到。新的片段先以新版本寫入，最後以資料庫交易切換有效版本。查詢過濾只見有效版本，未發布的部分結果不可外洩；不宣稱 LlamaIndex 自動把多個資料存放處合成同一交易。

刪除或撤銷存取時先讓來源不可檢索，再回收我們產生的內容、向量及快取；不刪使用者原檔。檢索使用與直接讀檔相同的授權政策，建過索引不代表所有任務都能讀；返回答案前再次確認來源存在、權限及版本，避免漏事件時仍引用舊內容。不同權限來源即使內容相同也不能共用可見性。改名能確認檔案識別時沿用內容計算，否則安全地當新路徑處理，不以路徑名稱猜它是同一檔。

索引、解析快取及備份均限制為該使用者可讀，服務不得對外開放；不得把內容寫入一般日誌。檢索文件一律視為資料，其中要求呼叫工具、改規則或外送內容的文字不得成為授權。撤銷讀取權限優先於快取命中。

## 邊建庫邊工作與資源限制

未建庫可先用檔名、路徑與已解析的全文搜尋；當前任務可限定少量候選直接讀取，並把該文件加進處理佇列。已完成的部分可查，沒有處理到的範圍明列；搜尋無結果不能宣稱整機沒有這份資料。原始資料本機解析與向量化；如果回答模型是遠端服務，提供原文片段仍是資料外送，必須遵守該範圍的外送設定。

初始保守預算：掃描一個工作、重解析一個工作；合計最多兩個 CPU 核心，背景容器記憶體上限 4 GiB，向量批次先從 8 片開始。GPU 預設不占用。前景查詢出現就暫停派發新的背景重工作；已跑的解析不保證能在任意行中斷，但須可終止子程序並稍後重做該文件。所有上限均為待測配置，不能保證每種 OCR 模型都能在此預算運行。

索引磁碟預算安裝時顯示；初版以 10 GiB 為保守上限提案，達上限就暫停新增、保留查詢與明確告警，不刪原檔、不宣稱建庫完成。輸出已發現／已解析／已向量化／排除／不支援／失敗／待處理各自數量、bytes 與最久等待時間；不把已掃 bytes 當內容理解百分比，不估計沒有實測根據的完工月份。

## 品質提升：AI 決定語意，程式守住原文與權限

2026-10-26 補充。先前只列結構切片，漏了語意分析、模擬提問與搜尋品質策略。以下是研究後的候選及驗收契約，尚未試接，也未包含在前次 Claude Code 審查中。AI 與程式不是互斥選擇：模型可建議切點、產生問題與排序，程式執行切分、保留來源、限制預算並拒絕不合法輸出。

### 切片有三種方式，不能混稱

| 方式           | 如何切                                               | 採用條件與驗收                                                                                                               |
| -------------- | ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| 結構切片       | 程式按標題、段落、表格、函式及長度限制切             | 全機初次建庫基準；用來源位置核對內容覆蓋，不能切掉表頭、數值單位或例外條款                                                   |
| 向量語意切片   | 用向量模型比較相鄰句群的語意差異，由程式選斷點       | 試接 LlamaIndex SemanticSplitterNodeParser；先驗中文斷句，與結構基準比較搜尋品質與成本                                       |
| 語言模型選切點 | 提供帶識別的句子／段落與有限上下文，模型回傳分組邊界 | 用於結構不清、主題混雜或搜尋失敗的文件；模型不重寫原文。程式核對識別存在、順序、完整覆蓋、長度及表格邊界；不合格回退結構切片 |

LlamaIndex 的語意切片是比較向量相似度，不等於每段都叫聊天模型讀一次；官方範例也提醒斷句主要針對英文，中文要另驗。[官方語意切片](https://developers.llamaindex.ai/python/examples/node_parsers/semantic_chunking/)。2024 年研究在其三類任務中未觀察到一致足以抵銷成本的收益；這不是否定語意切片，而是不能預設它一定比結構切片好。[研究](https://arxiv.org/abs/2410.13070)

### 其他方法、交付物與測試

| 方法                   | AI 與程式各交付什麼                                                                 | 如何驗收                                                                                                                   |
| ---------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 模擬提問作搜尋入口     | AI 為原文片段產生可回答的問題及支持位置；程式保存問題到原文的映射，搜尋命中後取原文 | 試接 QuestionsAnsweredExtractor，初始每片最多 3 問；驗問題是否真能由原文回答。生成問題不能當事實或答案來源                 |
| 模擬提問作測試題       | AI 提出問題、參考答案、證據位置及無答案案例；人工校對後成為測試資料                 | 與搜尋擴充問題分開，按文件家族隔離調整集及保留測試集；測試問題不得加入索引，近似重述也要檢查，不能自己出題自己判分就算通過 |
| 補片段背景             | AI 產生簡短說明，補文件名稱、主題、時間等上下文；程式將生成欄位與原文分開           | 比較有／無背景能否減少同名文件混淆；數字、實體及時間須受原文支持，答覆引用仍回原文                                         |
| 混合搜尋與重新排序     | 程式合併關鍵字與向量候選，再用排序模型逐一評估問題與候選的關聯                      | 固定候選數及延遲預算，比較正確證據是否更靠前；先做權限過濾，避免排序模型接到無權資料                                       |
| 小片段定位、補回上下文 | 程式找到精準片段，再補鄰接段落、所屬章節或表頭                                      | 測跨段指代、條件與例外是否保留；補回內容仍逐一核權，且受回答長度預算限制                                                   |
| 改寫問題與拆解子問題   | AI 提供少量不同問法或子問題，程式合併、去重查詢結果                                 | 初始最多 3 個額外查詢、最多 2 輪；保留原問法，驗型號、否定詞、日期與範圍未被改掉。遇到歧義不能任意猜                       |
| 證據檢查與拒答         | AI 將結論對應證據，程式核對來源版本與位置；人工抽查證據是否真正支持                 | 加入不存在答案、互相矛盾、過期版本及惡意文件指令；來源存在不等於結論正確，另一個 AI 的評分僅供輔助                         |

現成來源：LlamaIndex 提供問題與背景的[資訊抽取組件](https://github.com/run-llama/llama_index/blob/main/docs/src/content/docs/framework/module_guides/indexing/metadata_extraction.md)、[查詢融合組件](https://developers.llamaindex.ai/python/framework-api-reference/retrievers/vector/)，另有[鄰句補回範例](https://docs.llamaindex.ai/en/v0.10.34/examples/node_postprocessor/MetadataReplacementDemo/)。後者是舊版範例，採用時必須確認固定版本介面。Anthropic 的[Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)研究支持比較片段背景、關鍵字／向量混合與重新排序；其資料集結果不能當本案改善幅度。

### 怎麼兼顧全機效率與品質

先交付結構切片及混合搜尋基準；第一輪品質比較先試重新排序與補回上下文，再分別測背景說明、模擬提問、語意切片、問題改寫。高成本生成工作只在熱門、重要或已有失敗案例的文件背景執行，不把全機所有片段送語言模型後才可用。這是本案的試驗順序，不是宣稱某個方法一定最佳。

生成欄位記錄來源版本、模型、提示版本與設定；來源異動要使相關問題、背景及向量同步失效。模型選切點可能改變後續片段，因此「改一節只重算受影響片段」的範圍包含相鄰邊界及衍生內容，不能保證只重算一片。所有 AI 處理遵守既有資料外送限制；未配置獲准模型時保持基準可用，不偷偷改用外部服務。已有 4 GiB／CPU 預算不能推論足以跑新增語言模型，先量測，不夠就延後增強工作。

### 交付及驗收標準

每個候選交付固定版本設定、切點／生成問題／背景等衍生資料、原文映射、失敗與回退紀錄，以及同題比較報告。不是只交一段模型回答。

沿用至少 60 題，依中文、表格、程式碼、跨段、無答案分組，人工預標正確原文與必要證據。先鎖文件與題目切分，再調參；測試集原文可正常索引，但保留題目與參考答案不可用於產生搜尋擴充或調參。每次只增加一個方法，最後另測組合，避免把其他改動造成的差異歸功於切片。

報告至少列出 Recall@10（前十筆找回必要證據的比例）、nDCG@10（相關證據是否排前面）、引用支持率、答案正確率、無答案時的拒答表現、建庫時間、模型用量、峰值 RAM 及查詢第 95 百分位耗時。固定相同來源版本、回答模型及輸入預算；生成步驟重複測試並報波動。小題庫只作試接篩選，不當成穩定泛化證明。

選型門檻：不得新增越權引用或錯誤來源，且符合既有資源限制；保留測試集須呈現可重現的目標品質改善，不能只有平均分數上升而掩蓋某類文件退步。失敗對照要故意換錯引用、拿掉必要上下文、加入無根據模擬問題、撤銷權限，證明檢查能抓到問題。若品質沒有改善或成本超標，保留基準，不為技術名稱保留套件。

## 驗收與開發順序

1. **固定樣本與版本**：先建立合成測試集，涵蓋散落目錄、100,000 個檔案、1 GiB 大型文字檔、表格、掃描 PDF、郵件附件、TS／RS、至少一個設計圖格式及損壞檔。固定 CPU／RAM／磁碟、文件雜湊、依賴版本、模型與授權證據。大檔不可只造稀疏空洞檔冒充解析量。
2. **第一個可用切片**：CLI 啟動不等待掃描完成；服務已安裝就緒時，目標 5 秒內接受任務。測試資料可先全文找到，再驗向量查詢。與未開索引的同機基準比較，前景固定操作的第 95 百分位耗時增加不超過 20%；達不到就降背景資源或換接法，不先說高效。
3. **更新閉環**：已監看的 1 MiB 內文字文件，無排隊時目標 60 秒內更新完成；OCR／大檔只承諾可觀察的進度與排程，不冒用同一時限。重送事件、連續儲存、改名、刪除、權限撤銷、離線磁碟、解析中改檔、重啟及事件遺失都有正反測試。
4. **品質與節省**：沿用 60 題知識檢索門檻，另加上述格式與異動案例。量測首次／第二次建庫的讀取 bytes、解析次數、向量片數、耗時及峰值 RAM；相同內容第二次不得重新向量化，改一節只應計算受影響片段，變更切片／模型版本則要正確失效。全文與向量各自記錄效果，中文不得只驗英文樣本。
5. **安裝交付**：P05a（發現、常用格式、監看、引用與失效）改為 P03b 完整 CLI 安裝版的前置；P03a 可以先交內部檔案任務預覽，但不稱整機知識產品完成。P05b 補齊 OCR、大型文件與已列專業格式；P06 Memory、P07 Computer Use 照原需求繼續。全格式能力未齊不可宣稱「已理解電腦所有資料」。

試接優先順序是 Docling 的格式／記憶體、LlamaIndex 片段快取與更新語意、中文檢索、容器掛載監看。任何一項硬條件不過，先回到已研究的替代品比較，不擴寫自製引擎。原程式品質、錯誤注入與真實桌面驗收門檻不減。
