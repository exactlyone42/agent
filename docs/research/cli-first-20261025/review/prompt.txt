## PLAN.md
# Agent Platform：先做可安裝 CLI，再走向 ADE／IDE

研究日期：2026-10-25。這是開發順序與產品方向提案，不是已完成的功能。本輪研究與審查不代表產品實測；沒有安裝競品、修改產品程式或部署。

## 建議

先做能完成真實任務的 CLI（終端指令工具），同時交付可直接下載的執行檔。穩定後再提供 npm 安裝入口，接著做 ADE（以派工、監督與驗收 Agent 為主的桌面工作台）；IDE（以人工編輯、導航與除錯為主的開發環境）保留為後續方向。

三件事分開決定：CLI 是操作方式；npm／安裝包是交付方式；Rust／TypeScript 是實作語言。npm 可以只負責挑選、啟動 Rust 執行檔，不要求核心改寫成 JavaScript。CLI 本身也應能安裝，不必等桌面版才交付使用者。

本案的差異應是「授權清楚、停止可靠、能接續、結果有證據」，先在終端證明這些能力，再讓桌面提高派工與審查效率。此順序是本案建議，不能由競品目前有 CLI 與桌面版，倒推它們全部都依相同順序開發。

## 核心與介面如何共用

![建議架構：不同入口共用任務執行與驗證](architecture.svg)

圖為建議設計，不是目前已存在的系統。CLI 直接呼叫共用 Rust 核心；桌面以隨應用啟停的子程序，透過結構化訊息取得事件、送出授權及取消。桌面不解析終端畫面的文字來判斷成功，也不另做第二套 Agent 迴圈。此子程序不是常駐背景服務；無介面仍持續執行的工作，留到容器 worker 階段。

Gateway 維持獨立模型 API，任務狀態與寫檔授權留在 Agent Platform。第三方 Agent 的既有訂閱登入不等於可透過 Gateway 任意轉用；將來若整合外部 CLI，使用其支援的程序介面與原有認證，不匯出它們的秘密。

為避免第一次使用就要求架資料庫，建議 CLI 任務狀態改用本機 SQLite；知識庫、多人服務與向量檢索再按原計畫使用 PostgreSQL。這是對原技術計畫的明確修訂提案，尚未實作或搬移資料。只做一個本機狀態實作，不先建雙資料庫抽象；P01 要以交易、中斷恢復與兩個程序搶同任務的測試決定是否可採用。

前景任務先維持一個工作資料夾一個寫入者。狀態資料與使用者原始檔分開；憑證不可出現在命令列參數、一般日誌或成果報告。未驗證成功只能顯示等待、失敗或結果未明，不能因模型宣告完成就成功。

### SQLite 適不適合

建議單機 CLI／Tauri 用 SQLite 保存任務；同機一個任務擁有者控制執行。知識索引仍用本機 PostgreSQL／pgvector，資料庫不共用任務真相。SQLite 的優點是免架伺服器、交易完整、可隨程式交付；不是因為資料小才用，也不代表它能替我們執行或停止工作。

別人的做法：Codex 的 state 模組使用 SQLite，本輪讀到實際連線設定及狀態、佇列等資料庫路徑；其 rollout 資料與 SQLite 並存，不能說全部執行都只靠 SQLite。[Codex 原始碼](https://github.com/openai/codex/blob/main/codex-rs/state/src/sqlite.rs)。LangGraph 把流程快照與跨任務記憶分開；官方把 SQLite 列為本機開發保存方式，PostgresSaver 用於持久服務，不能把 SQLite 套件存在說成大型服務推薦。[LangGraph 保存設計](https://docs.langchain.com/oss/python/langgraph/persistence)

| 動作 | SQLite 保存什麼 | 執行核心必須做什麼 |
| --- | --- | --- |
| 執行 | 領取者、嘗試次數、工具意圖、回執、驗證結果 | 短交易搶任務；模型與工具執行時不持有資料庫交易 |
| 授權 | 誰批准哪個工具、參數摘要、範圍、有效期限與使用狀態 | 執行前再次核對；參數或範圍改變就重新判斷，不能沿用籠統批准 |
| 取消 | 先存取消請求，之後存已停止或結果未明 | 禁止新工具、停止子程序並核對；遠端操作可能已生效，不能假稱回滾 |
| 接續 | 已完成步驟、未完成意圖與外部操作識別 | 先核對舊執行者已停止；未知副作用查外部回執，不能直接再做一次 |

本案採單一任務資料庫、WAL（讓讀取與寫入較少互相阻塞）與短交易；同時仍只有一個寫入交易。重要授權及執行意圖以 FULL 同步設定驗收，鎖等待與重試有上限；資料庫只放本機磁碟，不放 NFS 或同步雲端資料夾。備份用 SQLite 備份介面，不只複製仍在寫入的主檔。[官方適用範圍](https://sqlite.org/whentouse.html)、[WAL 限制](https://sqlite.org/wal.html)

取消與領取必須在同一資料庫條件更新，避免取消後又派發。接續使用執行世代識別，舊執行者的回報不可覆蓋新狀態；這個識別本身不能阻止外部工具繼續寫，仍須實際停止舊程序。無法確認停止時維持「結果未明」，禁止重啟有副作用步驟。資料庫交易無法和任意外部 API 形成一次性交易；優先使用工具支援的冪等識別（重送也不重複執行），否則查證或人工處理。

P01／P04 要測兩程序搶同任務、授權與取消競爭、工具前後崩潰、磁碟滿、鎖超時、資料升級及備份恢復；先不宣稱效能或可靠接續已通過。若未來跨機 worker 要共享任務，或量測顯示寫入等待破壞互動目標，再採伺服器任務庫；不讓遠端程序直接開 SQLite 檔。

## RAG、流程編排與 Rust 套件選擇

RAG（先查自己的資料，再根據查到的內容回答）是正式交付範圍，不因 CLI 先行而取消。前版把它併在 P05–P07 一列，漏寫套件與驗收細節；本節補齊。P03 是檔案任務的早期可用版，P05 必須在 CLI 階段完成知識問答，不必等桌面；只有 P03 通過不能稱完整 Agent Platform 已完成。

| LangSmith | 追查每一步發生什麼，並評測回答及 Agent 表現         | 使用者寫的「LANSTRING」可能指這個，尚未確認。官方支援 OpenTelemetry，也就是通用的執行追蹤格式；Rust 可評估透過此格式串接，不必為追蹤改用 LangChain。[官方追蹤介面](https://docs.langchain.com/langsmith/trace-with-opentelemetry)                                                                                                                                                                                                                    |
| Rig       | Rust 原生的模型與 Agent 組件                        | 是本 repo 已登記的核心候選，不是 LangChain 的 Rust 官方版；先驗既有固定版本，不追著 main 換版。[專案來源](https://github.com/0xPlaygrounds/rig)                                                                                                                                                                                                                                                                                                      |
| Swiftide  | Rust 原生的文件匯入、切段、建立索引、檢索與回答流程 | 原始碼提供 indexing/query 管線；列為 P05 的資料處理候選。與 Rig 有功能重疊，僅在既有組件缺少所需能力時採用，不同時建立第二套 Agent 迴圈。[專案來源與範例](https://github.com/bosun-ai/swiftide)                                                                                                                                                                                                                                                      |

所以「有 Rust 可用」成立於**已有 Rust 專案與候選組件**，不等於「LangChain／LangGraph／LangSmith 三者都有官方、完整、已驗證的 Rust 等價版」。這些不是每個都必裝的套件組合；RAG 也不依賴一定要用 LangChain。

### 本案採用順序

1. **P01 選執行核心**：延續 Codex 與 Rig 的同題比較，不另開第三套主迴圈。本機 `Cargo.toml` 已將 `rig-agent`、`rig-core` 固定在 `55cd481a2421fd5da468b5bd6afc6ac876883599`；這只證明依賴已登記，本輪未重新編譯或驗證 RAG。
2. **P02／P04 驗流程能力**：先測選定核心的授權、取消、保存與接續。只有具體缺口需要分支流程時，才試接社群 Rust 圖式框架；用相同崩潰、重播與副作用案例比較。名稱含 LangGraph 不保證恢復安全。
3. **P05 選資料處理組件**：以整機知識庫方案的 Docling＋LlamaIndex 作首次試接；Rust 負責控制，不自造文件解析器。Swiftide／langchain-rust 用同題比較後再決定是否替代。採用前鎖定版本、授權與依賴。
4. **P02 起留下可追查事件，P08 完成評測**：沿用 Rust tracing／OpenTelemetry 與本機獨立驗證器；LangSmith 是可選查看與評測平台，不是任務成功的裁判。未獲資料外送與服務費用授權，不把文件、提示或工具內容送到外部平台。

這是選型優先序，尚未完成 Swiftide、langchain-rust 或 Rust 圖式框架的建置、維護狀況與相容性驗收；不宣稱它們可以直接替換既有核心。候選先以固定資料測試，不以星數、套件名稱或 README 宣傳判定成熟度。

# 整機知識庫：先可用，再逐步讀懂資料

## 採用的方案

安裝後即可交代任務，索引在背景執行；不等待掃完整顆硬碟。先發現檔案位置、大小與格式，再按用途解析內容、依結構切片、建立向量。正在工作的資料先做，大型手冊與報告另有處理名額；其他資料持續補齊，更新只處理有變動的文件及片段。

推薦組合是 **Rust 入口與工作控制＋Docling 解析／切片＋LlamaIndex 處理管線＋本機 PostgreSQL／pgvector**。Rust 用現成 walkdir 與 notify 做檔案發現和異動通知。這是待試接的組合，不是已互通的產品；不重寫解析器、向量引擎、OCR 或第二套 Agent 迴圈。

| 責任 | 復用什麼 | 本案只補什麼 |
| --- | --- | --- |
| 列出檔案與異動通知 | Rust walkdir、notify | 範圍政策、工作順序、缺漏核對、重啟續跑 |
| 文件解析與結構切片 | Docling；按需要選其本機 OCR | 隔離呼叫、版本及頁碼／表格／附件位置映射 |
| 程式結構 | Tree-sitter 的 Rust 介面與對應語法套件 | 將函式／型別及行號交給切片階段，不自寫 TS／Rust 語法分析 |
| 批次處理、快取、文件識別 | LlamaIndex IngestionPipeline | 穩定識別、版本發布與範圍契約；禁用自動掃全庫刪除策略 |
| 全文與向量查詢 | PostgreSQL＋pgvector | 僅查目前有效版本及有權限來源；中文檢索另驗 |
| 本機向量模型 | multilingual-e5-small 作首個測試候選 | 固定模型版本、批次大小與查詢／文件前綴；若品質不過再比較替代模型 |

LlamaIndex 內建文件雜湊判定和處理快取，但不保證我們的解析器參數、權限與多表更新自然一致，必須補同版測試。[處理管線](https://developers.llamaindex.ai/python/framework/module_guides/loading/ingestion_pipeline/)

### 為什麼沒有直接裝所有研究過的工具

- **Recoll** 適合現成全文搜尋與電子郵件；它的「只即時監看部分目錄，其餘定期核對」值得採用。但同時加入它與另一套知識資料庫，會增加兩套索引、解析與失效同步。本案先用它作檔案搜尋品質對照。[官方監看說明](https://www.recoll.org/usermanual/webhelp/docs/RCL.INDEXING.MONITOR.html)
- **sist2** 有檔名快速掃描、內容限制與增量掃描，適合作效能對照；不是把完整文件結構交給 RAG 的現成保證。其內容截取上限不能冒充全文件已讀。[官方用法](https://github.com/sist2app/sist2/blob/master/docs/USAGE.md)
- **Khoj** 有同步與片段雜湊復用，可參考處理方法，但不另啟完整聊天／Agent 平台。[原始碼](https://github.com/khoj-ai/khoj/blob/master/src/khoj/processor/content/text_to_entries.py)
- **Swiftide／langchain-rust** 保留比較資格；此次優先 Docling 與 LlamaIndex 是為了復用文件結構與既有處理管線，不為了全 Rust 再造 Python 已有能力。若同題試接證明 Rust 組合更簡單且品質不退，再修訂選型，不能同時養兩套。

## 安裝與部署

首個驗收平台為 Linux x64。CLI 是原生程式；長駐的索引服務、Python 解析與 PostgreSQL 都在本機容器，埠只綁 127.0.0.1。解析器不連網、不執行文件巨集、不取得模型供應商憑證。已允許的來源以唯讀掛載供索引服務讀取，輸出與資料庫使用獨立資料目錄。

完整產品安裝包含容器環境檢查、已核准的本機模型與服務啟動；不要求使用者手工建資料表。若容器或模型缺少，基本 CLI 仍可工作，畫面明列「知識庫尚未就緒」，不能宣稱整機功能已裝好。尚未取得的模型與套件大小、授權、版本在試接前核對，不偷偷下載或用付費 API 補上。

CLI 關閉不關閉已啟用的索引服務；提供暫停、繼續、查看進度與停用。索引服務與任務工具的取消分開：停止一次 Agent 任務不等於清除知識庫；暫停建庫要停止後續內容處理並保存位置。

macOS／Windows 之後另驗本機事件與容器掛載；不能把 Linux 的監看能力直接推論到 Docker Desktop。notify 官方列有網路磁碟、容器與監看數量限制，偵測失效時改分區定期核對，而非假稱即時。[notify](https://docs.rs/notify/latest/notify/)

## 全機發現與有順序的處理

「全機」指目前使用者獲准可讀的本機磁碟與資料來源，並非只看當前 repo。安裝時展示範圍與排除規則；預設納入文件、下載、桌面、專案與其他可讀資料目錄，背景逐個補齊其他目錄。額外磁碟逐個列明；雲端未下載項目、加密容器、其他使用者資料及應用程式線上帳號各自標示邊界。

快速發現只讀目錄與檔案資訊，不先讀每個大檔做全文雜湊，也不保證列完整機瞬間完成。以小批目錄保存位置；當前工作區與明確點名檔案可先處理，不等全機發現結束。檔名副檔名先篩選，再以檔頭辨認實際格式；不能只靠副檔名斷言支援。

候選優先序：使用者正在問的檔案、當前工作區、文件／下載／郵件資料、大型知識文件、其餘資料。大型檔案依格式與用途進獨立佇列，不把大於某大小當作無價值而永久跳過；大型影片、備份與編譯產物也不因體積大而擋住手冊。每處理四個前景候選，至少安排一個背景候選；長時間未處理者提高優先度，實際比率以效能驗證調整。

暫存、快取、套件目錄、編譯輸出與我們自己的索引目錄預設不做內容索引；敏感憑證資料不向量化。隱藏目錄不是一律排除，仍按類型判定。排除範圍可見，不能把排除計入完成。符號連結不跨出已授權範圍、不循環追蹤；重複檔可共用內容計算，但各路徑與讀取權限分開保存。

## 解析、切片、向量化

| 類型與例子 | 解析及切片方式 | 初版目標與邊界 |
| --- | --- | --- |
| PDF、DOCX、PPTX、MD、HTML | Docling 保留章節、頁碼、表格；依結構切片 | 先支援文字文件；掃描 PDF 走本機 OCR，慢工作另排，不阻塞其他文件 |
| XLSX、CSV、ODS | 保留工作表、欄名、資料列與範圍；表頭隨片段保留 | 不把整本表格壓成摘要；公式與顯示值分開，不執行巨集，不宣稱能重算 Excel |
| EML、MSG、郵件附件 | 先抽主旨、寄件人、時間、內文及郵件關聯；附件作子文件 | Docling 的附件名稱不是附件內容解析，須把附件交給對應解析器；PST／OST／MBOX 為另行試接項目，不冒充已支援 |
| TS、TSX、RS 等原始碼 | Tree-sitter 按函式／型別切片，保留路徑、行號與必要上層名稱 | 不執行原始碼；結構切片不等於完整跨檔呼叫分析 |
| LaTeX、JATS XML 等專業文件 | 使用文件解析器支援的結構；公式、表格及引用位置保留 | 每種格式獨立驗收；不能把任意 XML 視為同一規格 |
| SVG、PNG、JPG 與設計預覽 | 提取文字／本機 OCR、保留來源與圖面位置 | 視覺內容尚未理解者明列；OCR 不等於理解設計語意 |
| DXF、DWG、PSD、AI、FIG、STEP、IFC 等設計原檔 | 先登記格式及可用預覽；專用工具逐種評估 | 不宣稱通用解析器能讀懂。DXF 可試 ezdxf；DWG 及其他原檔的結構、圖層、尺寸與元件須獨立驗證 |

以上是要交付的支援矩陣，不是本輪已跑過的格式。Docling 官方列格式及必要額外依賴，舊 DOC／XLS 等轉換可能需 LibreOffice。[格式清單](https://docling-project.github.io/docling/usage/supported_formats/)、[Tree-sitter](https://tree-sitter.github.io/tree-sitter/)、[ezdxf 邊界](https://ezdxf.readthedocs.io/en/stable/introduction.html)

流程先產生可重用的結構化解析結果，再切片，最後向量化。每片保留文件版本、來源位置、解析器與切片設定；章節名稱、表頭可補到片段，但不可覆寫原文。Docling HybridChunker 可按結構與模型長度分割／合併並重複表頭，直接復用，不自行按固定字數粗切。[切片文件](https://docling-project.github.io/docling/concepts/chunking/)

模型先試本機 multilingual-e5-small，按模型要求區分 query／passage 前綴，切片長度與 tokenizer 對齊；不把模型宣告的多語能力當中文、程式碼、表格檢索已合格。未通過固定題庫就改候選，不能改題目遷就模型。[模型來源](https://huggingface.co/intfloat/multilingual-e5-small)

大檔先登記、提取可取得的目錄與頁面資訊，再以解析器確實支援的頁段／工作表單位處理；不假設每種檔案都能串流或任意切開。不能分段的格式在隔離程序內整檔解析，超過時間／記憶體上限就標示延後或失敗，保留原因與下次策略，不永久無聲跳過，也不無限重跑。

## 異動、刪除與接續

原生事件只用來加速，並非完整真相。先啟動監看並緩衝事件，再列出範圍，核對掃描期間異動；事件合併後批次處理。常用目錄即時監看，其餘輪流核對檔案資訊；重啟或事件溢出時重查受影響目錄。移除磁碟、權限不足與確認刪除分開，不因磁碟沒掛載就清除全庫。

單文件流程為：發現版本 → 解析 → 切片 → 向量就緒 → 發布。解析前後核對來源是否改變；變了就不發布混合版本。新一版未完成前，舊版標示過期且預設不回答；新版驗證完整後才切換有效版本。每個工作有固定識別與單一執行者，崩潰後查已完成階段再續跑。

LlamaIndex 文件識別、處理快取與資料庫的有效版本是不同責任：快取鍵必須包含片段實際內容、解析／切片設定、模型與向量維度；不能因路徑相同就重用。新的片段先以新版本寫入，最後以資料庫交易切換有效版本。查詢過濾只見有效版本，未發布的部分結果不可外洩；不宣稱 LlamaIndex 自動把多個資料存放處合成同一交易。

刪除或撤銷存取時先讓來源不可檢索，再回收我們產生的內容、向量及快取；不刪使用者原檔。返回答案前再次確認來源存在、權限及版本，避免漏事件時仍引用舊內容。不同權限來源即使內容相同也不能共用可見性。改名能確認檔案識別時沿用內容計算，否則安全地當新路徑處理，不以路徑名稱猜它是同一檔。

## 邊建庫邊工作與資源限制

未建庫可先用檔名、路徑與已解析的全文搜尋；當前任務可限定少量候選直接讀取，並把該文件加進處理佇列。已完成的部分可查，沒有處理到的範圍明列；搜尋無結果不能宣稱整機沒有這份資料。原始資料本機解析與向量化；如果回答模型是遠端服務，提供原文片段仍是資料外送，必須遵守該範圍的外送設定。

初始保守預算：掃描一個工作、重解析一個工作；合計最多兩個 CPU 核心，背景容器記憶體上限 4 GiB，向量批次先從 8 片開始。GPU 預設不占用。前景查詢出現就暫停派發新的背景重工作；已跑的解析不保證能在任意行中斷，但須可終止子程序並稍後重做該文件。所有上限均為待測配置，不能保證每種 OCR 模型都能在此預算運行。

索引磁碟預算安裝時顯示；初版以 10 GiB 為保守上限提案，達上限就暫停新增、保留查詢與明確告警，不刪原檔、不宣稱建庫完成。輸出已發現／已解析／已向量化／排除／不支援／失敗／待處理各自數量、bytes 與最久等待時間；不把已掃 bytes 當內容理解百分比，不估計沒有實測根據的完工月份。

## 驗收與開發順序

1. **固定樣本與版本**：先建立合成測試集，涵蓋散落目錄、100,000 個檔案、1 GiB 大型文字檔、表格、掃描 PDF、郵件附件、TS／RS、至少一個設計圖格式及損壞檔。固定 CPU／RAM／磁碟、文件雜湊、依賴版本、模型與授權證據。大檔不可只造稀疏空洞檔冒充解析量。
2. **第一個可用切片**：CLI 啟動不等待掃描完成；服務已安裝就緒時，目標 5 秒內接受任務。測試資料可先全文找到，再驗向量查詢。與未開索引的同機基準比較，前景固定操作的第 95 百分位耗時增加不超過 20%；達不到就降背景資源或換接法，不先說高效。
3. **更新閉環**：已監看的 1 MiB 內文字文件，無排隊時目標 60 秒內更新完成；OCR／大檔只承諾可觀察的進度與排程，不冒用同一時限。重送事件、連續儲存、改名、刪除、權限撤銷、離線磁碟、解析中改檔、重啟及事件遺失都有正反測試。
4. **品質與節省**：沿用 60 題知識檢索門檻，另加上述格式與異動案例。量測首次／第二次建庫的讀取 bytes、解析次數、向量片數、耗時及峰值 RAM；相同內容第二次不得重新向量化，改一節只應計算受影響片段，變更切片／模型版本則要正確失效。全文與向量各自記錄效果，中文不得只驗英文樣本。
5. **安裝交付**：P05a（發現、常用格式、監看、引用與失效）改為 P03 完整 CLI 安裝版的前置；P03 可以先交內部檔案任務預覽，但不稱整機知識產品完成。P05b 補齊 OCR、大型文件與已列專業格式；P06 Memory、P07 Computer Use 照原需求繼續。全格式能力未齊不可宣稱「已理解電腦所有資料」。

試接優先順序是 Docling 的格式／記憶體、LlamaIndex 片段快取與更新語意、中文檢索、容器掛載監看。任何一項硬條件不過，先回到已研究的替代品比較，不擴寫自製引擎。原程式品質、錯誤注入與真實桌面驗收門檻不減。
