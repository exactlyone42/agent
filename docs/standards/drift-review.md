# 過時檢查（drift review）

用途：定期找出「文件、圖和程式對不上」的地方，以及可以刪掉的過時文件。程式先篩出可疑處，再請兩個 AI 看；AI 只提建議，**不會改檔、不會刪檔**，要不要動由人決定。

## 怎麼運作

1. **程式篩選**（`cargo xtask drift-scan` 只做這一步，不呼叫 AI、不花任何額度）：
   - 死參照：文件裡用反引號或連結寫到的路徑（只認 `crates/`、`docs/`、`scripts/`、`sql/`、`loops/`、`.cargo/`、`.repo-policy/` 開頭），但 Git 裡找不到這個檔案或資料夾。
   - 文件落後：文件提到的程式，比文件本身晚改超過 30 天。時間取自 Git 提交紀錄，不是檔案修改時間。
   - 圖落後：兩張現況圖（`docs/diagrams/current-class-diagram.pdf`、`docs/diagrams/mortal-agent-architecture.pdf`）比 `crates/` 裡最新的檔案舊超過 14 天。圖檔 AI 讀不了，只列時間差給人看。
   - 不看 `loops/`、`docs/run-history/`、`docs/standards/records.md`：這些是帶日期的紀錄，本來就會過時。
2. **Claude 先審**：每個有可疑處的檔案，由 Claude 用唯讀工具（只能讀、搜尋，不能寫）讀實際檔案，回答三選一：沒問題、內容需更新、整份可刪。回答要附證據：檔案、行號與該行的原文片段。
3. **程式驗證證據**：程式回頭讀那一行，原文片段對不上、行號不存在或少於 4 個字，整個判定丟棄（報告列在「證據對不上」）。AI 講得再有道理，沒有通過這一關就不算數。
4. **Codex 複核**：只有證據通過的「需更新／可刪」才交給 Codex（同樣唯讀），它自己去讀檔案，回答同意或不同意。兩個都同意才列為「兩個 AI 都認為需要處理」；Codex 不同意的另列一區，不當成結論。

## 怎麼用

| 命令                     | 做什麼                                                                            |
| ------------------------ | --------------------------------------------------------------------------------- |
| `cargo xtask drift-scan` | 只跑程式篩選，印出可疑清單，結束代碼一律為成功                                    |
| `cargo xtask drift`      | 完整流程，報告寫到 `.runtime/drift/report-<時間>.md`；AI 工具失敗時結束代碼為失敗 |

`.runtime/drift/` 內還有：`state.json`（哪個檔案、內容雜湊、何時審過）、`logs-<時間>/`（每次呼叫的完整輸出與錯誤輸出）、`running.lock`（執行中的標記，程式結束會自己移除）。

## 成本與上限

- 每次最多審 8 個檔案；還沒審過的先審，其次是最久沒審的，剩下的下一次再審，報告會寫「留待下次」幾個。
- 檔案內容和可疑處都沒變、且 28 天內審過，就略過。檔案一改就會重審。
- 每次 Claude 呼叫預算上限 1 美元（`--max-budget-usd`），單次呼叫最久 15 分鐘，逾時就中止。
- AI 工具失敗（沒網路、逾時、回覆格式錯）：這次中止，已審完的照常記錄，沒審完的不標成已審，下次重來。不會自動重試。
- 同時只能跑一個。如果前一次被強制殺掉留下 `running.lock`，確認沒有執行中的程序後手動刪掉。

## 排程（每週一 03:30）

用 systemd 使用者計時器（Linux 上以使用者身分跑的排程，這台機器已有同類計時器）。檔案在 `scripts/schedule/`：

- 安裝：在 develop 分支的工作目錄執行 `scripts/schedule/install.sh`。不在 develop 會拒絕安裝，避免排程跑在未合併的分支上。
- 退回：執行 `scripts/schedule/uninstall.sh`，停用計時器並刪掉兩個單元檔。
- 手動觸發一次：`systemctl --user start agent-drift.service`，看紀錄用 `journalctl --user -u agent-drift.service`。
- 排程以使用者的 HOME 執行，所以 `claude`、`codex` 要在該 HOME 已登入。

## 取捨

- **不讓 AI 動檔案**：誤刪或誤改的代價大於人工看一份清單；報告只是建議。
- **證據由程式驗證**：模型可能編造不存在的引文，所以每個「有問題」都要程式讀回原文才算。代價是有真問題但引文抄錯時會被丟掉，下一輪或換人再看。
- **時間用 Git 提交時間**：檔案系統的修改時間在重新複製後會全部變成同一天，不可靠。
- **圖不交給 AI**：PDF 版面 AI 讀不準，只提醒人去比對。
- **一次只審 8 檔**：控制額度與單次時間，用 28 天輪替涵蓋全部。

## 限制

- 只在 Linux 驗過；Windows、macOS 沒有 systemd，排程要另外設計，本文沒涵蓋。
- 死參照只認上面列的目錄開頭的路徑；寫成相對於其他位置的短路徑、或用文字描述的參照看不到。
- 「規劃中、還沒建立的檔案」也會被標成死參照，由 AI 判斷是不是只是計畫，可能誤報。
- 文件落後只比對「提到的程式的最新提交時間」，不比對內容，只是提高優先審查的線索。
