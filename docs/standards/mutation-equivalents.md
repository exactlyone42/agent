# 變異測試：不需測試的改動與平台缺口

變異測試會故意改壞程式一小處，看測試能不能發現。有些改法不會改變任何行為，測試本來就不可能發現，叫「等價改動」。排除清單放在 `.cargo/mutants.toml`，每一項都要在這裡說明原因；新增排除必須先證明真的等價。

## 已排除的等價改動（Linux 實測確認過其他漏抓都已補測試）

| 位置                                    | 為什麼改了也沒差                                                                                                |

## 不跑變異的入口

`Task::run` 與 `Task::all`（在 `crates/xtask/src/task.rs`，xtask 是本 repo 跑各項檢查的工具程式）只負責啟動整套檢查，測它們等於在測試裡再跑一次完整檢查。它們的內容由 `check_all` 與 `run_steps` 的測試涵蓋，所以「把整個函式換成空實作」這類替換不進變異清單（排除設定寫在 `crates/xtask/src/plan.rs`）。

## 平台缺口：只在 Windows 編譯的程式

input.rs 第 30、61、69、82 行屬於 Windows 專用程式，Linux 不會編譯，測試也就碰不到這幾行，所以變異永遠「沒被抓」。`crates/xtask/src/check_all.rs` 因此在非 Windows 平台排除這幾行；Windows 實機必須不排除並跑完（`identity_guard` 與 `file_identity` 現有測試只在 Windows 執行）。

`single_link.rs` 第 11 行（非 Unix 版本，固定回傳「只有一個連結」）同樣只在 Windows 編譯，同樣排除。Windows 上還沒有測試能分辨硬連結（同一份檔案內容的另一個檔名），實機要補。Windows 實機結果出來前，這塊不能宣稱已驗收。
